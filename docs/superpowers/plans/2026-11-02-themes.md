# Themes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Users switch themes in a Settings window. A theme sets colors, fonts, corners and density, and built-in and future plugin themes use the same `themes` point.

**Architecture:** A `settings` module owns the window and a `settingsSections` point. A `theme` module owns the `themes` point, pure logic ported from Cloudy Canvas, a saved choice, and `applyTheme`, which writes one style tag and caches it so `index.html` can paint it before React. `tokens.css` stays as the fallback, so Cloudy Dark needs no module to show.

**Tech Stack:** TypeScript, React 19, Zustand, Tailwind v4 `@theme`, Zod, Tauri 2.

**Spec:** `docs/superpowers/specs/2026-11-02-themes-design.md`

## Global Constraints

- Cloudy Dark at Default density looks exactly like today's app.
- Base branch: `themes`, cut from `solids-composite-gradients`. Merge after it.
- Stage 4 (Tasks 8 and 9) comes last, after keyframes and all the rest of this plan are done.
- Git commits have no `Co-Authored-By` line.
- The theme is never in the project file or history. Theme code is never read by preview or export.
- Corners never exceed 8px.
- Reference code: `../cloudy-canvas/src/shared/core/themes/` and `../cloudy-canvas/src/pages/settings/sections/appearance/`. Canvas file names are hyphenated; Clip's are dotted.
- Agents get no theme tools. A plugin font file, UI scale and more built-in themes are out of scope.
- Rule 3: the only test kept is `read.test.ts` (Task 1).

## Review Focus

1. A theme value with `url(` or `@import` is refused. Pinned by `read.test.ts`.
2. A saved plugin theme that isn't loaded: falls back, keeps the saved id, and doesn't crash at startup.
3. A broken localStorage value, for `cloudy-clip.theme` or the CSS cache: the app starts in Cloudy Dark.
4. The `extends` chain that loops or names a missing theme: resolves without hanging.
5. Export with Light on matches export with Dark, byte for byte in the pixels.

## Stage 1: themes work

### Task 1: Theme logic

**Files:** Create `src/modules/theme/theme.types.ts` and everything in `src/modules/theme/logic/`.

**Interfaces:**

- Produces: `ThemeDefinition`, `ResolvedTheme`, `ThemeDensity`, `ThemeChoice`, `ThemeFamily`; `THEME_TOKEN_NAMES`, `isThemeToken(name)`; `readTheme(data: unknown): { theme: ThemeDefinition; ignored: string[] }`; `resolveTheme(theme, get: (id: string) => ThemeDefinition | undefined): ResolvedTheme`; `themeCss(theme: ResolvedTheme, density?: ThemeDensity): string`; `activeTheme(choice, systemDark, lastAppearance, get): ActiveTheme`; `groupFamilies(themes): ThemeFamily[]`.

- [ ] **Step 1: Write the failing test** in `logic/read.test.ts`:

```ts
const base = { id: "t", label: "T", appearance: "dark", preview: PREVIEW };
it("refuses a value that could load from the network", () => {
  expect(() => readTheme({ ...base, tokens: { surface: "url(https://x.test/a.png)" } })).toThrow();
  expect(() => readTheme({ ...base, tokens: { surface: "@import 'x'" } })).toThrow();
});
it("refuses a value that could end the declaration", () => {
  expect(() =>
    readTheme({ ...base, tokens: { surface: "red; } body { display: none" } }),
  ).toThrow();
});
it("leaves out unknown tokens and reports them", () => {
  expect(readTheme({ ...base, tokens: { "canvas-grid": "#000" } }).ignored).toEqual([
    "canvas-grid",
  ]);
});
```

- [ ] **Step 2:** Run `pnpm vitest run src/modules/theme/logic/read.test.ts`. Expected: FAIL, `readTheme` is not defined.

- [ ] **Step 3: Implement.** Port Canvas's `read-theme-definition.ts`, `resolve-theme.ts`, `theme-css.ts`, `theme-density.ts`, `group-theme-families.ts`, and `active-theme.ts` as pure functions.

  - `logic/tokens.ts`: every semantic name in `tokens.css`, plus `clip-video`, `clip-audio`, `clip-type`, `clip-composition`, `clip-foreground`, `ink-hover`.
  - Drop `products`. Add `fonts.hand`. Density metrics are the spec's table, plus `--control-px`, `--track-h-video`, `--track-h-audio`.
  - `resolveTheme` keeps Canvas's loop guard, and the chain ends at `cloudy-dark`, which lists no tokens. Default corners 4, 6, 8, clamped to 0..8.
  - `themeCss` writes `html:root { … color-scheme }`, with corners as `--radius-xs` (`control / 2`), `--radius-sm`, `--radius-md`, `--radius-lg`, and fonts as `--font-sans`, `--font-mono`, `--font-hand` only when set.
  - Unsafe values match `/[;{}<>\\]|url\(|@import/i`.

- [ ] **Step 4:** Run the test, then `pnpm typecheck`. Expected: PASS, no errors.

- [ ] **Step 5: Commit** `feat(theme): theme definitions, resolving and CSS`.

### Task 3: The theme module

**Files:** Create the rest of `src/modules/theme/` except `ui/`, and modify `src/app/bootstrap.ts`, `index.html`.

**Interfaces:**

- Consumes: Task 1 logic, `BUILT_IN_THEMES`.
- Produces: `themes` point, `defineTheme`, `themeRef` with `ThemeApi { store; list(): RegisteredTheme[]; active(): ActiveTheme; onChange(listener): Disposer }`, `setTheme` command `theme.set`. No MCP tools.

- [ ] **Step 1: Store.** `createThemeChoice()` in `theme.store.ts`, reading `cloudy-clip.theme` with a Zod schema. A broken value gives the defaults: fixed, `cloudy-dark`, `cloudy-light`, `cloudy-dark`, density null.

- [ ] **Step 2: Apply.** `applyTheme(active, density)` in `theme.apply.ts`, from Canvas's `apply-theme.ts`, without the export scope and without `.dark`. Skip writing when the CSS is unchanged. Failing to save the cache is ignored.

- [ ] **Step 3: Service.** `createThemeService({ points, store, log })`: reads the point through `readTheme` (bad ones logged and sent to `notify`, once), keeps the `matchMedia("(prefers-color-scheme: dark)")` listener, re-applies on any of the three triggers, returns the API plus `dispose`.

  `PointReader.get` doesn't give the contributor, so `ThemeDefinition` has an optional `owner`, read as `"app"` when unset. The plugin loader will set it.

- [ ] **Step 4: Command.** `theme.set` validates ids against the list, then writes the store. Fail with `theme.unknown` for an unknown id. Don't add MCP tools: agents can't change the user's theme.

- [ ] **Step 5: Wire.** `theme.module.ts` with `tier: "feature"`, `commands`, `setup` contributing `BUILT_IN_THEMES` and returning the API. Add it to `MODULES` in `bootstrap.ts`.

- [ ] **Step 6: Before first paint.** In `index.html`'s `<head>`, an inline script reads `cloudy-clip.theme-css` and adds `<style id="cloudy-theme">`, all in `try`. Add `<style>html{background:#14171b}</style>` before it, so the first run doesn't flash white.
