# Elements Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every kind of clip is an element declared once with `defineElement` (properties, layout, picture, timeline display, creation); validation, defaults, the inspector panel, drawing, hit-testing, creation and MCP are generated from it, and text and media become the first two elements.

**Architecture:** A new core module `element` owns the declaration API, the `elements` / `sharedGroups` / `propTypes` points, the pure logic (schemas, resolve, minimize, layout resolution) and the generic commands `element.setProps` / `element.resetProps`. `project` becomes kind-agnostic (`clip.props`). `preview`, `transform`, `timeline` and `inspector` read the element registry instead of branching on `kind === "text"`. `text` keeps only its element declaration, its drawing, its preset command, its two custom controls and the canvas editor.

**Tech Stack:** TypeScript strict (`noUncheckedIndexedAccess`), React 19, Zustand 5, Immer 11, Zod 4 (`z.toJSONSchema`), Vitest (node), lucide-react.

**Spec:** `docs/superpowers/specs/2026-10-29-elements-design.md` (read "Settled calls" and "The generic command").

## Global Constraints

- All rules in `CLAUDE.md`. Each task updates the README of every folder it changes, in the README template of `docs/modules.md`.
- Done means `pnpm typecheck && pnpm lint && pnpm test` pass at the end of **every** task (no task leaves the build broken).
- Commits: no `Co-Authored-By` lines (user memory overrides the harness reminder).
- Values on a clip: `clip.props`, only fields that differ from `defaults(format)`; groups merge one level deep. Shared group values stay at their own key (`clip.transform`).
- Command ids `<module>.<action>`, MCP tools `<module>_<snake>`: `element.setProps` / `element_set_props`, `element.resetProps` / `element_reset_props`, `element_describe` (tool only), `timeline.addElement` / `timeline_add_element` (written `addClip` in Task 10 below; renamed while implementing, since `timeline.addClip` already places media), `transform.reset` / `transform_reset`, `text.applyPreset` / `text_apply_preset`.
- Removed (code, exports, MCP tools, README rows): `text.add`, `text.setText`, `text.setStyle`, `transform.setClipTransform`, `PreviewApi.previewTextClip` / `onTextOverride` / `textClipOverride`, `TextOverride`, `inspectorSections`, `clipFit`, every `Text*` export of `project`.
- Error codes: `element.clip_not_found`, `element.mixed_kinds`, `element.unknown_kind`, `element.invalid_props`, `element.read_only`, `timeline.needs_source`, `timeline.kind_mismatch`, `timeline.track_not_found`; text keeps `text.weight_unavailable`, `text.italic_unavailable`.
- Callbacks in `ElementDefinition`, `SharedGroup`, `PropType` and `PictureDefinition` use **method syntax** (`draw(ctx, props, env): void`), so a typed element (`ElementDefinition<TextProps>`) fits the `elements` point (`AnyElement`) without `any`.
- A text clip with empty `props` draws, measures and hit-tests exactly as a text clip without `style` does today (`defaultTextStyle` numbers unchanged).
- Warnings about layouts (unknown command, control, section layout or prop type; unplaced or duplicate path) are logged **once per distinct message** per kernel, never per render.

## Review Focus

1. **Props stay minimal through edits:** setting a field back to its default removes it from `clip.props`; an emptied group disappears; undo restores the exact previous object. Test in Task 2.
2. **Format changes:** a clip whose `size` is not stored follows the new format's default after `project.setFormat`; a stored size does not change. Test in Task 1 (`resolve` with two formats).
3. **Missing plugin pieces:** a layout naming an unregistered command, control, section layout or prop type renders a disabled warning row and logs once, and the rest of the panel works. Tests in Task 3 (logic) and Task 8 (warning dedupe).
4. **Live edit interrupted:** a slider drag whose clip is deleted or deselected before release clears its preview override and sends no command. Test in Task 7.
5. **Split and trim of non-media elements:** splitting a text clip copies `props` to both halves (deep copy, not shared), and trimming keeps `sourceIn` at 0. Test in Task 5.

- Produces:
  ```ts
  type ResolvedItem =
    | { type: "field"; path: string; control: string; label: string }
    | { type: "row"; items: ResolvedItem[] }
    | { type: "sub"; title: string; header?: string /* toggle path */; items: ResolvedItem[] }
    | { type: "command"; id: string; control?: string; label?: string; icon?: string };
  interface ResolvedSection {
    key: string;
    title: string;
    order: number;
    layout: string;
    header?: string;
    items: ResolvedItem[];
  }
  interface LayoutIssue {
    message: string;
  } // "element \"note\", section \"Box\": path \"box.pdd\" does not exist"
  function resolveLayout(
    element: ResolvedElement,
    controlOf: (path: string, spec: PropSpec) => string,
  ): { sections: ResolvedSection[]; issues: LayoutIssue[] };
  type PanelCommandCheck =
    | { ok: true; field?: { name: string; schema: z.ZodType } }
    | { ok: false; reason: "missing" | "no_clip_ids" | "too_many_fields"; message: string };
  function checkPanelCommand(id: string, command: CommandDefinition | undefined): PanelCommandCheck;
  ```
- Rules (from the spec, each one a test):
  - No `layout`: section `"General"` (key `general`, order 0) with the top-level non-group fields in declaration order, then one section per element group (order = 10·index + 10) titled by its `label`, header = its `toggle`; then each supported shared group's own section (its `layout` or generated, order from `group.order`, e.g. transform 900). Hidden fields are skipped everywhere.
  - A group path alone in `items` → the section takes it over (title defaults to the group's `label`, `header` = toggle, items = the other fields). Next to other items → a `sub` with header = toggle. `{ group, items }` → `sub` with only those fields. `{ title, items }` → `sub`. A `sub` inside a `sub` → issue, flattened into the outer one.
  - A toggle field is never listed again as a row inside its own section/sub.
  - Unplaced, non-hidden fields → issue (`… property "x" is not placed`) and an `"Other"` section (order 10000). A path placed twice outside a `row` → issue, the second ignored. An unknown path → issue, skipped. A shared group not in `supports` is never shown, even if named.
  - `label` default: the spec's `label`, else the path's last segment split on camelCase and capitalized (`letterSpacing` → `Letter spacing`).
  - `checkPanelCommand`: missing command → `missing`, message `command "<id>" is not registered (is its module loaded?)`; input not a `z.object` with an array `clipIds` → `no_clip_ids`; more than one other key → `too_many_fields`; otherwise `ok` with the one other field if any.
