# speed

How fast a clip plays its file: one constant speed or a ramp, backwards or forwards, and frames held still. The value is `Clip.speed` in `project`, since core modules read it; this module owns the commands, tools, the box over the clip and the inspector section.

- **Tier:** feature
- **Requires:** `project`, `junction`, `media`, `timeline`, `preview`, `inspector`, `keyframe`
- **Contributes:** `clipActions` (Speed..., Freeze frame), `appOverlays` (`speed.box`), `inspectorSections` (`speed.section`, tab `video`, right after Transform), `keyTargets` (`speed.keys`: `speed.rate`)
- **Points it owns:** —
- **API** (`useModule(speedRef)`): `view` (`boxClipId`, `ripple`: per kernel and never in history)
- **Files:**
  - `speed.commands.ts`: the commands below. `logic/retime.ts`: `retime` (the new layout at a rate), `resize` (the new layout at any length, which both `retime` and a ramp use), `writeSpeed` (never stores the defaults), `writeRamp`, `flattenRamp`.
  - `speed.keys.ts`: the key target of `speed.rate`, and what a ramp does to a clip's length.
  - `speed.menu.ts`: the menu entries. `logic/timecode.ts`: `parseTimecode`.
  - `ui/`: `SpeedFields` (the same fields in both places, so they always agree), `SpeedBox`, `SpeedSection` (adds Direction), `TimecodeField`, `speed.edit.hook.ts` (drag steps reach the preview through `previewProps` and the clip's width through the DOM; the release is one `speed.set`, or one `keyframe.set` on a ramped clip).
- **Invariants:** only clips that play a file have a speed (`canChangeSpeed`), not text, images, stickers, solids or composition clips. A clip keeps its start and its part of the file, so its length changes. Linked clips take the same speed. A speed equal to the defaults is never stored, so a normal clip has no `speed`. `sourceTimeAt` in `project` is the only place a rate meets clip time.
- **Ripple:** on, what follows on the track moves with the clip's end, with partners, and junctions shrink as for a trim; anything unlinked in the way refuses with `timeline.overlap`. Off, nothing else moves: a slower clip stops at the next one and the rate returned is the one applied, and a junction on the clip's end, or one on its start that would no longer fit, refuses with `speed.joined`, so a transition never changes unasked.
- **Pitch correction:** WebKitGTK keeps the pitch at any rate and ignores `preservesPitch`, so correction on needs nothing and off runs the pitch worklet at the rate (see `docs/superpowers/specs/2026-11-02-speed-preview-check.md`). Export uses `atempo`, or `asetrate` when off.
- **Freeze frame:** a hold is a clip at `rate: 0`: one frame of the file, no time of its own (`followsFileTime` is false), so it trims to any length and has no sound. It keeps the clip's transform and composite, and takes the values keys give at that time, as static values with no `animation`, so the picture doesn't jump when it ends.
- **Ramps:** `speed.rate` (0.1 to 10, no loops, `RAMP_PATH` in `project`) is a key track, added with `keyframe_set` or the diamond on the Speed row. Its keys sit on the file's time like every track, so a clip's part of the file stays and its length follows, in the same command, moving what follows as `speed.set` does with the last Ripple choice: the track and the length go on linked clips too (keys shifted by their own `animationOrigin`), so a key edited from either row works. Without ripple, a transition on the clip's end refuses with `speed.joined` and a ramp that outgrows its room with `timeline.overlap`. A ramp that would leave less than one frame fails with `speed.out_of_range`. When the last key goes (`keyframe_remove`, `keyframe_clear`), the clip plays the same part of the file at the rate that key leaves: `commitStatic` only writes the rate, since the length needs the track that just went, and `afterWrite` does the rest from `before`. While a clip has a ramp its Speed slider and presets show the rate at the playhead and write a key there (`keyframe.set` on `speed.rate`, as the sound fields do), Direction and Duration stay disabled, `speed.set` with `rate` or `duration` fails with `speed.ramped`, `speed.reset` drops it. A ramp never meets Reverse: `speed.reversed_ramp` from either side, the key from `afterWrite` (a reversed clip still lists `speed.rate`, so `fields` stays safe to call everywhere). A hold lists no `speed.rate`. `speed.rate` on the stored clip is what the clip goes back to, never what plays: read `rateAt`. The preview plays a ramp at `rateAt` every frame; export's sound follows it in tempo steps, one per 250 ms where the rate changes and one per stretch where it holds (see `export`).
- **Reverse:** elements only play forwards, so a reversed clip plays a copy of its file that runs backwards, made by the native side in pieces (`src-tauri/src/media/reversed.rs`) and asked for through `media.reversedUrl`. Until the copy is ready that clip is left out of the frame and the rest plays on. `sourceTimeAt` stays in the original file's time; `elementTimeAt` mirrors it for the copy. Export draws from a full-quality copy, and reverses sound with `areverse`.

| Command             | MCP tool             | Notes                                                                   |
| ------------------- | -------------------- | ----------------------------------------------------------------------- |
| `speed.set`         | `speed_set`          | `rate` or `duration`, `pitchCorrection`, `reversed`, `ripple`           |
| `speed.reset`       | `speed_reset`        | Back to normal speed, forwards, with pitch correction, without a ramp   |
| `speed.freezeFrame` | `speed_freeze_frame` | Splits and puts in a 3 s hold, moving what follows. `speed.unsupported` |

Fails with `speed.unsupported`, `speed.out_of_range`, `speed.joined`, `speed.ramped`, `speed.reversed_ramp`, `speed.clip_not_found` and `timeline.overlap`.

**Not yet:** speed on composition clips. Very high speeds may drop frames in preview, not in export. Windows (WebView2) hasn't been checked.
