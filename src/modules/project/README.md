# project

The project document: compositions, imported media, tracks and clips. Everything the user makes
lives here, so every change is undoable and readable by agents.

- **Tier:** core
- **Requires:** —
- **Contributes:** —
- **Points it owns:** —
- **API** (`useModule(projectRef)` / `ctx.require(projectRef)`): `store`, a patchable store of
  `ProjectState`. Read it freely; change it only through commands (`ctx.mutate`). Other modules edit
  it with their own commands. `view` says who has which composition open: `openFor(actor)`,
  `setOpen`, `closeTab`, `requireOpen` (throws `composition.none_open`), `formatFor`, `reset`. An actor whose
  composition is gone falls back to Main, then to none. `useOpenComposition()` and `useOpenFormat()`
  read it for the user.
- **Files:**
  - `project.types.ts`: `ProjectState`, `Composition`, `Track`, `Clip`, `ClipTransform`, `ClipPlacement`,
    `SharedGroupValues`. A `Clip` names its element in `kind` (`"media"`, `"text"`, a plugin's)
    and stores only the values that differ from the element's defaults in `props`; `mediaId` is
    set for clips that play a file; shared group values (`transform`) live under their own key.
  - `project.grade.types.ts`: the grade's types (`ClipGrade`, `GradeNode` and its six kinds, `NodeRef`, `GradeLimit`, `CorrectionValues`, `GradeGroup`, `Lut`, `Still`), re-exported by `project.types.ts` so the rest of the module imports them from there. It is a separate file only to keep `project.types.ts` short.
  - `project.store.ts`: `DEFAULT_FORMAT`, `createEmptyProject()`.
  - `project.view.ts`: the view above. `project.testing.ts`: `seedProject(seed)`, one composition `c1` for test fixtures.
  - `logic/compositions.ts`: `contains(state, outer, inner)`, `settleCompositions` (the policy's `settle`, innermost first, inside every step: Extend to fit lengths, placements shortened to their composition, a transition that no longer fits removed with the left clip ending at the next one's start; it never moves a `start`).
  - `logic/fields.ts`: `projectPolicy`, the store's `StorePolicy`: what lets a step be undone past others' newer steps. `diff` lists changes by field (one level into plain objects; a created or deleted entity is one change), `repair` rebuilds `clipIds`, each `trackOrder`, `compositionOrder`, `mediaOrder`, `binOrder` and `solidOrder`, and `validate` refuses a missing Main, tracks without a composition, a composition inside itself, missing tracks or media, overlaps, stale junctions, two junctions on a cut, an item or bin pointing at a missing bin, a bin inside itself, a marker without its composition, a path without its composition or with fewer than two points, a clip following a missing path or one of another composition (so an undo that would leave a follower on nothing is refused), and any grade `validateGrade` refuses (clip, version, composition, shot group and still). Its `settle` also drops a `gradeGroup` naming a deleted group, a shot group no clip is in any more (with its grade, in the same step that took its last clip; `gradeGroups` goes when empty) and a node's `lut` naming a LUT that is not in `luts` (ids starting with `BUILTIN_LUT_PREFIX`, `"builtin:"`, are built-in looks and stay). `markers` is a record compared field by field, so each marker undoes on its own, and so is `paths` (may be missing, like the three below); `gradeGroups` likewise, while `luts` and `stills` are whole entities like `media`. These three may be missing: while both sides have one it is compared per entry, and when one side lacks it the whole collection is one change (writing an entry under a missing parent would do nothing). `repair` also reconciles `stillOrder`.
  - `logic/fields.grades.ts`: `dropDeletedGrades` (a deleted shot group or LUT is let go by the clips and nodes that named it) and `gradeProblem` (the first broken grade in the document, which `validate` reports).
  - `project.selectors.ts`: `requireComposition(state, id)` (the composition, or the `composition.not_found` failure: the one guard every command uses), `orderedTracks(state, compositionId)`, `trackClips`, `clipEnd`,
    `compositionOf`, `compositionClips`, `compositionContent`, `placementsOf`, `formatOf(state, clip)`,
    `formatOfTrack`, `frameDuration`, `isMediaInUse`, `followsFileTime(state, clip)` (false for text and
    images, which have no time of their own).
  - `project.geometry.ts`: `clipPlacement(format, sourceSize, transform)`, the one place a clip's
    transform becomes a rectangle in the frame (the preview engine and the canvas tools both use it);
    `clipTransform(clip, live?)` (the saved transform or the identity, with a live patch merged
    over it), `IDENTITY_TRANSFORM`, `clipComposite(clip, live?)` and `IDENTITY_COMPOSITE` (a blend mode and opacity, missing means Normal at 100%; both fill partial values from the identity), `normalizeRotation`. The fit (`contain` for media,
    `none` for text at its natural size) comes from the clip's element.
  - `logic/color.schema.ts`: `hexColor`, the one `#rrggbb` schema (both cases accepted, stored lowercase) that solid, media info, composition and element colours and gradient stops share.
  - `logic/links.ts`: `partnersOf`, `withPartners` (linked clips, moved here from the timeline).
  - `logic/junctions.ts`: junction data rules. `junctionBetween`, `junctionsOfClip`,
    `allowedOverlap(state, left, right)` (the junction's duration, also for the linked sound pair on
    another track, else 0), `rippleMoves`, `applyMoves` (pure, keeps `clipIds` sorted),
    `findLayoutConflict`, `staleJunctions`.
  - `logic/ease.ts`, `logic/animate.ts`, `logic/content.ts`, `logic/keys.ts`: keyframes, see below.
  - `createProjectModule(initial)` seeds the document in tests.
- **Invariants:** tracks, clips and junctions stay in flat records with project-wide ids, and a track belongs to one composition, so a clip or track id says which composition it means; track order is top → bottom (higher video tracks are drawn on top);
  `Track.clipIds` is sorted by `start` and clips on a track never overlap, except by `allowedOverlap` (junctions); times are microseconds;
  `Clip.transform` is optional, and each field missing is the identity (fitted and centered): `x`/`y`
  where the pivot sits, offset from the frame's center in output pixels (the picture's center while
  the pivot is at its default), `scale` relative to fit, `scaleX`/`scaleY` width and height factors
  on top of it (negative flips that axis), `rotation` clockwise degrees, `pivotX`/`pivotY` the pivot
  in the picture as a fraction of its size from its center (-0.5 is the left or top edge). Scale,
  stretch and rotation happen about the pivot. `clipPlacement` folds the pivot into the placement's
  center and gives the flip as `flipX`/`flipY` (its `width`/`height` stay positive); every drawer
  mirrors by them after rotating.
  Video tracks hold pictures only; audio tracks hold sound (a video file's sound sits there as a
  clip of the same media). Clips sharing a `Clip.linkId` are linked (picture and sound of one
  video) and are edited together by the timeline until unlinked.
- **Paths:** `ProjectState.paths` (missing in projects without any) holds motion paths (`MotionPath`: `compositionId`, `name`, `closed`, `points`, each a `PathPoint` in output px from the frame's center with `in`/`out` handle offsets; cubic Béziers between points, last to first when closed). A clip follows one through the `follow` shared group (`ClipFollow`: `pathId`, `progress`, `orient`; owned by the `path` module), and its `transform.x`/`y` are then an offset from the path. `logic/path.ts`: `pathPointAt(path, progress)` (by arc length from a 32-samples-per-segment table cached per path object; an open path holds its ends, a closed one wraps; `angle` in degrees clockwise, 0 = right) and `pathLength`. `logic/follow.ts`: `followShift(clip, paths)` (what the path adds, read from an animated clip; null without a path), `followedClip(clip, time, paths)` (`animatedClip` plus that shift written into `transform`; every placement of a picture reads clips through it, so the engine, export and canvas agree), `bakeFollow(clip, paths, at)` (the clip left where it was at `at`: the shift added to the static position and rotation and to their keys, `follow` and `follow.*` tracks dropped), `copyFollowedPaths(draft, clipIds, compositionId)` (a copy of each followed path in that composition, the clips repointed) and `scalePath(path, kx, ky)`. `NO_FOLLOW` is the group's default.
- **Markers:** `ProjectState.markers` holds bookmarks on a composition's timeline (`Marker`: `compositionId`, `time`, `note`, `color`, one of `MARKER_COLORS`). `compositionMarkers(state, id)` lists one composition's, by time; `project_get_state` shows them per composition. The `marker` module owns their commands and UI.
- **Junctions:** `ProjectState.junctions` holds things on the cut between two adjacent clips of one
  track (`Junction`: `kind`, `trackId`, `leftClipId`, `rightClipId`, `duration` = their overlap, `props`).
  Clips on a track overlap only by the `allowedOverlap` of the pair.
- **Saving:** `workspace` owns the file; `view.reset()` is what opening one calls.

**Speed:** `Clip.speed` (`ClipSpeed`: `rate`, `pitchCorrection`, `reversed`) says how a clip plays its file; missing means normally. `Clip.duration` is the length on the timeline and the part of the file played is that at the rate (`sourceSpan`). `logic/speed.ts` holds `DEFAULT_SPEED`, `speedOf`, `sourceTimeAt` (the file's time at a timeline time, the only place a rate meets clip time), `elementTimeAt` (the same for a reversed copy), `canChangeSpeed` and `sameSpeed`. A `rate` of 0 holds one frame. The `speed` module owns the commands.

**Speed ramps:** a track at `RAMP_PATH` (`speed.rate`) overrides `speed.rate`, and its keys sit on content time, so the rate is a function of the file. `logic/ramp.ts`: `rampOf(clip)`, `rampTimeAt(track, from, to)` (the timeline length of content `from..to`, `∫ dc / rate(c)`; the first and last rate outside the keys; signed) and `rampContentAt(track, from, elapsed)` (its inverse). Both read a table of that integral, one cell per 1/120 s of content cut at the keys, read at each cell's middle, and cached in a `WeakMap` by track, since a track is never changed in place. `filePlayed(clip, elapsed)` in `logic/speed.ts` is the one place both kinds of clip meet: `sourceSpan`, `sourceTimeAt`, `contentTime` and `clampTrim` go through it. `timeOfContent` follows the ramp, and `rateAt(clip, time)` says what plays at a time. These read the track, never `speed.rate`, which `animatedClip` overwrites on its copy each frame; `speedOf` fills in that copy's partial speed. `sameSpeed` compares ramps from each clip's own origin. Rounding a length to a whole microsecond moves a clip's file span by up to the rate, in file microseconds.

**Sound:** `Clip.sound` (`ClipSound`) says how a clip on an audio track sounds; missing means as the file does. `logic/sound.ts` holds `DEFAULT_SOUND`, `soundOf`, `dbToLinear`, `fadeLevel` (at each end the longer of the clip's fade and a junction's crossfade, `CrossfadeLevels`; the two ends multiply, as the export's two `afade` filters do), `pitchShift`, `panSide(pan)` (`"L"`, `"C"` or `"R"`, the one label of a pan's side, for the inspector's Pan row and the mixer's pan), `formatDb(db, digits?)` (a level for people: a real minus sign, a plus above 0, `−∞` for silence; the mixer, the meters and `audio`'s gain badge) and `minimize(value, defaults)` (undefined at the defaults, so a default is never stored), which commands, preview and export share. `logic/sound.schema.ts` holds the volume limits `VOLUME_DB_MIN` / `VOLUME_DB_MAX` (−60 / 12 dB, which every volume control and the fader's taper take) and the Zod schemas of sound values (`volumeDbSchema`, `panSchema`, `eqBandSchema`, `eqSchema`) that every command setting them is built from. The store policy keeps fades within their clip on every change. The `audio` module owns the commands.

**Mix:** `Track.mix` (`TrackMix`: `volumeDb`, `pan`, and optionally `busId`, `effects` and `volumeLine`) says how an audio track sounds in the mix, and `Composition.mix` (`CompositionMix`: `master`, `activeMix` `"a"` or `"b"`, `otherMix`, a `MixSnapshot` of the other mix, and `delivery`, the `DeliverySettings` (`standard`, `loudnessLufs`, `peakDbtp`) the mix is delivered against, shared by both mixes, missing meaning YouTube's) holds the master, the groups and the two mixes. The master (`MasterMix`) has `volumeDb` and optionally `trimDb` (its input trim, -24..24 dB, on the sum before the fader, its line, pan and effects, after stems are taken; what `sound`'s Match target sets; 0 never stored; `TRIM_DB_MIN`/`TRIM_DB_MAX`, `trimDbSchema`), `pan` (a balance of the stereo mix, a track pan's law; 0 never stored), `muted` (silences the mix; stems are taken before the master; false never stored), `effects` and `volumeLine` (as a track's: a `KeyTrack` on timeline time, the fader an offset on top; a line with no keys is never stored), dropped at their defaults by `minimizeMaster` (which `minimizeCompositionMix` runs). As with its volume and effects, an inner composition's master pan, mute and line are heard only when it's the one open, not when placed. A group track is a `MixBus` (`id` from `createId("bus")`, `name`, `volumeDb`, `muted`, optionally `effects`) in `CompositionMix.buses` (and `MixSnapshot.buses` for the other mix); an audio track sends to one through `TrackMix.busId`, missing meaning Master, and a group sends to Master only. An empty `buses` is never stored (`minimizeCompositionMix`). A duck's `listensTo` may name a group; the store's `settle` drops ids of deleted tracks and groups. The live values are on the tracks, in `master` and in `buses`; `otherMix` is the one swapped in by switching. Both are missing until changed and **never stored at the defaults** (`minimizeTrackMix`, `minimize`): an untouched project has none, plays as it did and saves as before. The project file stays at version 3 because the fields are optional and the file schema is loose: an older app opens such a file and ignores them. `logic/mix.ts` holds `DEFAULT_TRACK_MIX`, `DEFAULT_COMPOSITION_MIX`, `trackMixOf`, `compositionMixOf`, `minimizeTrackMix` `trackBus(composition, track)` (the group a track sends to there; undefined for Master or a group it lacks) and `soundInPlacement(track, nestingPan, gain, pan, bus?)` (the gain and pan of a clip inside a placed composition once the inner track's mix applies, times the volume of the inner group it sends to, with the pans of the inner tracks above added; a muted inner group silences its tracks as their mute does; the preview's `placeSound` and the export's mixdown both call it). `project_get_state` shows each composition's `mix` and each audio track's. The `sound` module owns the commands.

**Track volume line:** `TrackMix.volumeLine` is a `KeyTrack` (`blend` `"number"`, `min` -60, `max` 12) of the track's volume in dB whose keys' `t` is **timeline time**, never content time, so moving or splitting a clip never moves it. Evaluate it with `trackValue` (it holds the first level before the first key and the last after the last) and find where it bends with `keyMoments`; `simplify(points, tolerance)` (`logic/animate.ts`) thins `{at, value}` points to the ones off a straight line by more than the tolerance (export's envelopes, sound's strokes and fader passes); edit it with `writeKey`, `moveTrackKeys`, `withoutKeys` and `writeSpan`; `keyEase` (`logic/keys.schema.ts`) is the Zod schema of a key's ease, which `keyframe` and `sound` commands both take. The fader's `volumeDb` is an offset on top of it. A line with no keys is never stored, and it travels with the rest of the mix (mix A and B, duplicating a composition). The `sound` module owns the commands.

**Effects:** `TrackMix.effects` and `MasterMix.effects` hold a chain of `SoundEffect` (a union on `kind`: `eq`, `compressor`, `gate`, `deesser`, `limiter`, `denoise`, `duck`; each has an `id` from `createId` and `on`). Missing or empty means none, and an empty chain is never stored (`minimizeTrackMix`, `minimizeCompositionMix`), so a mix at the defaults without effects stores nothing. Effects are stored even when equal to a kind's defaults: adding one is a choice. `logic/effect.schema.ts` has one Zod schema per kind (`effectSchemas`, `soundEffectSchema`, `SOUND_EFFECT_KINDS`; the compressor's ratio is at least 1) that every command is built from. Their bounds are `EFFECT_RANGES` (by kind and field), which the Sound page's controls read too. A `duck` lists the tracks it `listensTo`; the store policy's `settle` removes a deleted track from every `listensTo` (live tracks and `otherMix` snapshots) in the same step. The schemas are strict (unknown fields refused) and a `listensTo` lists a track once. Duplicating a composition remaps its ducks to the copied tracks. **Noise reduction** (`logic/denoise.ts`), the one rule for which files get it: `heardDenoise(track, composition)` is what a top-level track's clips are heard through, its own when on with an amount above 0, otherwise the master's. It's rendered into each file, so it applies first, before clip volume and every other effect, wherever it sits in its chain; the master's is per file, for the tracks without their own, not a bus effect, and a clip is never reduced twice. Inside a placement the outer track's counts. `denoiseNeeds(state, compositionId)` lists every file heard through it when a composition plays (`DenoiseNeed`: `mediaId`, the `denoise` effect, `reversed`): clips of unmuted audio tracks that aren't disabled, placements included, images left out. The preview, the export's mixdown, the Sound page and the renderings all follow it. It is the third walk of which clips are heard, beside the export's `mixdown` (`walk`) and the preview's `resolveFrame`: the three must stay in step on what they skip (muted tracks, disabled clips, placements, images), so a change to one is made to all three. The `sound` module owns the commands.

**Masks:** `Clip.masks` (by id) with `maskOrder` (the order they apply in) and `Clip.matte` (`ClipMatte`: `trackId`, `by` alpha or luma, `invert`) cut a picture clip's picture; both are missing until used and never stored empty. A `ClipMask` has `name`, `color` (a `MarkerColor`), `on` (`false` or missing), `mode` (add, subtract, intersect, difference), `invert`, `opacity`, `feather`, `expansion`, `x`, `y`, `rotation` and a `shape` (`MaskShape`: rectangle, ellipse, star, heart, linear, mirror, or a closed `path` of `PathPoint`s by `PointId` with `pointOrder` and `scale`). A mask lives in the clip's **fitted picture space** (output px from the picture's center, the picture as `clipPlacement` fits it at the identity transform), so it depends on the picture's aspect only and a proxy and its master map it alike. `logic/mask.ts`: `maskPlacement(format, size, transform)` (the one mapping into the frame: center, rotation and signed per-axis factors `placed / fitted`; a point lands at `rotate((px*sx, py*sy), rotation) + (cx, cy)`), `maskOutline(mask)` (closed cubic segments in fitted picture px, null for linear and mirror), `maskLine(mask)` (a point, the unit normal and the mirror's half-width, for those two), `orderedMasks(clip)` and `scaleMasks(clip, k)` (every length and its keys, for resizing a composition; a whole-shape key is not scaled). `MASK_RANGES` holds the number ranges. `validate` (`logic/fields.masks.ts`) refuses an order not matching the masks, a value out of range, a path with under three points or an order not matching its points, a matte naming a missing track, a track of another composition or an audio track (its own track is allowed; the engine ignores it), and masks or a matte on an audio clip. `settle` drops a `matte` whose track is gone, in the same step as `listensTo`. `project_get_state` lists each clip's masks (id, name, kind, mode, on, invert) in order, and its `matte`. The `mask` module owns the commands.

**Grade:** `Clip.grade` (`ClipGrade`) says how a picture clip is colored; missing means as the file is. It is a graph: `nodes` by id (`Correction`, `ParallelJoin`, `LayerJoin`, `ChannelSplit`, `ChannelJoin`, `KeyJoin`) and `out`, a `NodeRef` (`"source"` or a node, with a `channel` only from a split); `input` is the camera color space (missing means Rec.709). `Composition.grade` grades a composition's whole frame, and `ProjectState.gradeGroups` (a grade that runs after the clip's own, named by `Clip.gradeGroup`), `luts`, `stills` and `stillOrder` hold the rest. `Clip.gradeVersions` / `gradeVersion` keep other versions by name. All are optional and **never stored at the defaults**: a `Correction.values` holds only fields that differ from `DEFAULT_CORRECTION` (wheels and the like are whole `{ x, y, m }` objects, curves are point lists), and `minimizeGrade(grade)` drops the rest (undefined for source straight to out). `logic/grade.ts`: `DEFAULT_CORRECTION`, `WARPER_POINTS` (36), `UNSAFE_KEYS` (keys values never hold), `GRADE_RANGES` (min and max by dotted field path such as `lift.x`, which the keyframe paths `grade.nodes.<id>.values.<field>` share), `LIMIT_RANGES` (a limit's numbers by path such as `color.hue`: hue in degrees 0 to 360 of the hue curves' circle, red at 0, wrapping through red when `hue[0] > hue[1]`; saturation 0 to 1 of full chroma; `lum` and `range` 0 to 1 of luma; softness and clean up 0 to 100), `gradeOf(clip)` (the grade or null), `correctionOf(node)` (its values over the defaults, filling a partial keyed value; own keys only, never a prototype) and `canGrade(clip, project)` (a video or image file, or a composition, on a video track). `logic/grade.validate.ts`: `gradeInputs(node)` and `gradeKeys(node)` (the pictures and the keys a node reads), `renameGradeKeys(node, rename)` (renames the key ids in place), `gradeReads(grade, id, of)` (whether a node reads another through pictures or keys), `validateGrade(grade)` (null, or the first problem: a ref to a missing node (by own key, so `toString` is missing), a picture ref (an input or `out`) naming a key join (it has a key, not a picture), a cycle through pictures or keys, `out` not reached from the source, a channel ref not from a split, a join with fewer than two inputs or `blends` not matching, a `limit.from` that is missing, not a correction or key join, in a cycle, or naming a node on the picture path that is not above it (`keyFromAbove`: its input reads it through pictures or keys; an off-path pick or a key join is allowed, Leader Seal's; a grade saved with a pick from a sibling branch fails like any invalid grade), opacity or strength outside 0 to 1 (or NaN), a correction value that is not an own field of `DEFAULT_CORRECTION` or has another type than its default (checked at every depth and in every list element: `__proto__`, `constructor` and `prototype` are never keys, a curve has 2 or more `[x, y]` points in 0 to 1 with x strictly increasing from 0 to 1, the matrix is 3 rows of 3, `warper.points` keys are grid indices 0 to `WARPER_POINTS - 1` (12 hues by 3 rings, 36) each holding exactly `{ dh, ds }`, `warper.pinned` holds such indices, the message names `values.<path>`), a value outside its range, warper offsets included: `dh` -180 to 180 degrees, `ds` -1 to 1, a limit's number outside `LIMIT_RANGES`, or a saturation, `lum` or brightness `range` pair running backwards). Commands check it before writing and `projectPolicy.validate` checks every grade in the document. `logic/grade.validate.ranges.ts`: `rangeProblem` (a value that is not finite or is outside `GRADE_RANGES`) and `limitProblem` (a limit's number outside `LIMIT_RANGES`, or a pair running backwards), split out of `grade.validate.ts`. `logic/grade.schema.ts`: `gradeSchema`, `INPUT_SPACES` (every `InputColorSpace`, for schemas and pickers), `gradeNodeSchema`, `nodeRefSchema`, `gradeLimitSchema`, `correctionValuesSchema` (shape only; the graph rules are `validateGrade`'s). The `tint` module owns the commands.

**Keyframes:** `Clip.animation` (a record of `KeyTrack` by path: `transform.x`, `fontSize`, `outline.width`) and `Clip.animationOrigin` hold animated values; both are missing until something is keyed, and a clip without them plays, exports and saves as before. A `KeyTrack` has `blend` (`number`, `color` or `step`), `shared` (the value sits under its own clip key such as `transform`, not in `props`), `min`/`max` (copied from the property), `after` (`loop` or `pingpong`; missing holds the last value) and `keys` sorted by `t`. A `Keyframe` has `id`, `t`, `value`, `ease` (`KeyEase`, what happens on the way to the next key; missing means linear) and `smooth` (handles in line; the editor's concern only). Key times are content time, never timeline time. `logic/content.ts`: `contentTime(clip, time)` (time since the clip's first frame, from `animationOrigin`, scaled by the rate through `speedOf` but not through `sourceTimeAt`, so it runs forward on a reversed clip and keeps running on a held frame; not clamped), `clipHasKeys(clip)` (true when `animation` or any stored grade version's `animation` exists: the guard for keeping `animationOrigin` on trim, split and group, so keys parked in a version keep their time), `timeOfContent` (its inverse) and `clampToClip` (a time within the clip's first to last microsecond). `logic/ease.ts`: `EASE_PRESETS` (Linear, Ease in, Ease out, Ease, Snap, Anticipate, Overshoot, Bounce, Elastic, Hold), `easeProgress(ease, u)` (a bezier's x is clamped to 0..1, its y is free; bounce and elastic are functions) and `presetOf(ease)` (exact match, else `"custom"`). `logic/animate.ts`: `keyMoments(track, from, to)` (the key times in `from..to`, in the keys' own time, loop and ping-pong repeats included: where a value starts or stops changing; the export samples envelopes there and the preview schedules a track's volume line there), `trackValue(track, t)` (holds outside the keys, blends numbers and `#rrggbb` colors along the left key's ease, steps the rest, clamps to `min`/`max`, loops or ping-pongs after the last key) and `animatedClip(clip, time)` (the clip with every keyed value written in place; the same object when nothing is keyed; a track with no keys, which a damaged file could hold, is skipped; shared values can come out partial, which `clipTransform` fills from the identity). The engine calls `animatedClip` only in `resolveFrame` and `visibleLayers`. `logic/keys.ts`, pure and returning new values: `writeKey(track, t, value, tolerance, ease?)` (updates the key within `tolerance`, keeping its id and ease, else inserts one with the previous key's ease), `moveTrackKeys(track, moves, tolerance)` (sets new times, drops unmoved keys a moved key lands on, sorts), `withoutKeys(track, ids)` and `withoutTracks(animation, drop)` (undefined when nothing is left, since a track never has zero keys), `writeSpan(track, from, to, points, fallback)` (the keys from `from` to `to` replaced by `points` (`SpanPoint`, `{t, value}`), linear between them, with a key 1 µs outside each edge at the value the track had there, or `fallback` when it has no keys, so the rest plays as before; the one after eases as the old track did; none where a key already sits; a track's volume line strokes and passes and `keyframe.writeSpan` write with it) and `mirrorEase(ease)` (a bezier reflected, other eases unchanged).
