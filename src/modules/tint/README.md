# tint

The Tint page, a tab between Edit and Sound, where colors are graded: corrections stored once as a graph, shown as layers (**Baby Seal**) or as nodes (**Leader Seal**), with Basics, wheels, curves, Color mix, Warper, Creative, limits, LUTs, Match and the RGB mixer, scopes beside them and the clips below. **The frame, the layer list, Basics, the wheels (Primary, Log, Bars, Zones), the curves, Color mix, the Warper, Creative, Limit, the RGB mixer, LUT and color, Match, and Looks and stills are real**: the viewer (the preview's own stage, so it plays), the clip strip, the current clip and the seal switch read the open project; the layer list (Baby Seal) reads and edits the real grade at the level the clips bar's switch shows (the current clip's own, its shot group's or the whole timeline's); Basics, the wheels, Curves, Color mix, the Warper, Creative, Limit, the RGB mixer and the LUT edit the selected layer (else the first correction; with none yet, the first edit adds one); the node graph (Leader Seal) reads and edits the same grade. A clip's saved grade already draws (every value of a correction and its LUT: Basics, all the wheels, the curves, Color mix, the warper, skin pull, the mixer, Creative and its limit by color and brightness or a shared key; and side-by-side, stacked and per-channel groups) in the preview, captures and export through the `tint.grade` filter, followed by its shot group's grade, and a composition's whole-timeline grade draws on its frame through the `tint.timeline` frame filter. The design is `docs/superpowers/specs/2026-11-03-tint-page-design.md`, the plan `docs/superpowers/plans/2026-11-03-tint.md`, the picture `docs/prototype/designs/tint-d-studio.html`.

- **Tier:** feature
- **Requires:** `project` (grade types and helpers, the strip), `preview` (the picture filter, `redraw`, playback, `gpuAvailable`, `PreviewStage`), `timeline` (the selection), `media` (probes for the strip's cards), `workspace` (`relinkKinds`, and its `ui` to open the relink dialog when a LUT file is missing), `keyframe` (`keyTargets`, `KeyAction`, `keyframe.set`), `inspector` (`useClipAtPlayhead`, so the tools show keyed values at the playhead)
- **Contributes:** **order of grades on one picture:** source → input conversion → clip grade → shot group grade (both on the clip's own picture, before it scales and blends) → the composition's whole-timeline grade on the composed frame (the spec's order: the group grade runs after the clip's own, since it carries the shared look). Each level with no grade adds no pass, so untouched projects draw exactly as before. Picture filter `tint.grade` (`pictureFilters`, order 100, `tint.filter.ts` `createTintFilters`): applies to a clip that `canGrade` with a grade or a shot group with a grade; its passes are `gradePasses(clip.grade, live, textures, aspect, show, videoRange, lutOf)` then the same for its group's grade (live values by the group's id), put together with preview's `chainPasses` in one run; frame filter `tint.timeline` (`frameFilters`, order 100): applies to a composition with a `grade`, passes `gradePasses(composition.grade, …)` with live values by the composition's id, at the top level and inside every placement, so a placed composition carries its whole-timeline grade (the spec's call 7). Captures: `TINT_CUT` (`TintCut { level, node }`: levels before it whole, that level up to `node` (null: none of it), the levels after it left out) and `TINT_WITH` (`TintWith { level, grade }`: that grade in place of the level's, every level drawn) apply only to the captured top-level clip (`info.path === clip.id`) and the top-level frame (`path` `""`), never inside a placement. Show applies at `view.level` only, and the levels after it are left out (the timeline grade too while Show is on below it). Of the picture filter: (curve and warper tables keyed by holder and node, `heldBy`, so a pasted grade sharing node ids never bakes another's away; `aspect` from the filter's `size`, for the vignette; `videoRange` from `videoRange()` in `tint.range.ts`, for the camera color space), so a grade shows in the preview, captures and export; live values are laid over it only when `target` is `"preview"`, so a capture or an export draws the saved document even mid-drag; so is Limit's Show (`view.showPicked`, passed as `gradePasses`' `show`), which never reaches a capture or an export. Its LUTs come from `luts` (`LutFiles`): `ready` is false while a correction's LUT file is being read, so no frame (and no first export frame) is drawn without it; a missing one is left out in the preview and captures, the preview telling the user once per file (`notify`), and an export fails with `tint.lut_missing` naming the file. One pair per kernel (`createTintFilters(live, view, media, luts)` → `{ picture, frame }`), since they read that kernel's live values and view (`redrawOnShow` redraws the preview when `showPicked` or `level` changes), with the media probes (each file's range) and its own lookup tables (`createGradeTextures`); page `tint.page` (`TINT_PAGE`; `appPages`, icon `Palette`); top bar item `tint.sealSwitch` (`topBarItems`, right: Baby Seal | Leader Seal; `topBarItems` has no page filter, so `SealSwitch` reads `pagesRef` and renders nothing unless the Tint page is open); relink kind `tint.luts` (`relinkKinds`: `LutRelinkRows`, the missing LUT files as workspace's `RelinkRow` tagged LUT, no note: Locate finds one file at a time); keybindings `tint.previousClip` and `tint.nextClip` (Up, Down; only on the Tint page) and `tint.bypass` (Shift+D) (`tint.bindings.ts`); key target `tint.keys` (`keyTargets`, `tint.keys.ts`: a clip's grade numbers, see Keyframes); the page has `keepsPlayback`, so Space plays and pauses on it
- **Commands** (all undoable; a `target` is `{ clipId }`, `{ groupId }` (a shot group) or `{ compositionId }` (the whole timeline), and every node command (`addCorrection`, `setCorrection`, `setCorrections`, `removeNodes`, `moveLayer`, `reset`, `group`, `ungroup`, `setGroup`, `wire`, `placeNodes`, `copy`) takes any of the three through `readGrade`/`writeGrade`, with no rule stricter than `validateGrade`; only a clip's grade has key tracks (`tint.setInput` takes `clipIds`, so a camera space is per clip only); each reads the grade, edits a copy with `logic/stack*.ts`, runs `minimizeGrade` and `validateGrade`, then writes once):
  - `tint.addCorrection` (`tint_add_correction`): `{ target, at?, values?, limit?, lut?, name? }` adds a layer (default: the bottom of the stack) and returns `{ nodeId }`.
  - `tint.setCorrection` (`tint_set_correction`): `{ target, nodeId, at? (a timeline time: keyed numbers get a key there, see Keyframes), patch: { values?, limit? (null removes), lut? ({ id, strength 0…1 }, null removes; the id must be in `ProjectState.luts`or start with`builtin:`, else `tint.lut_not_found`), opacity?, on?, name? } }`; each given value field replaces that field whole. A `limit.from` written by the patch (any limit on `tint.addCorrection`; other edits of a node keep its stored key unchecked, `validateGrade` still guarding the graph) is checked by `checkSharedKey` (`tint.guards.ts` (`readGrade`, `writeGrade`, `targetsOf`, `targetName`), `logic/keys.ts` `keyProblem`) before anything is written: it must name a key join or a correction whose limit limits something (its own pick or a shared one), else `tint.key_not_limited`, and not this one or one drawn from it, else `tint.key_cycle`.
  - `tint.setCorrections` (`tint_set_corrections`): `{ target, nodeIds, patch: { on?, opacity? } }`; turns several corrections on or off or fades them in one undo step, all or nothing (one animated field, or a node that is no correction, refuses the lot: `tint.animated`, `tint.node_not_found`). A sealed card's eye and fade use it.
  - `tint.group` (`tint_group`, `tint.group.commands.ts`): `{ target, nodeIds, kind: "parallel" | "layer" | "channels" }` puts items that follow one another in one list into a group (`logic/stack.group.ts` `groupLayers`; side by side and stacked need two or more, per channel one to three, into the red, green, blue branches) and returns `{ joinId }`; `tint.cant_group` otherwise.
  - `tint.ungroup` (`tint_ungroup`): `{ target, joinId }` takes a group apart (`ungroup`: the branches' items in a row, top branch first), and the join's and split's key tracks go; `tint.not_a_group` when `joinId` isn't a group the stack shows.
  - `tint.setGroup` (`tint_set_group`): `{ target, joinId, patch: { opacity?, on?, blends? } }` for a side-by-side or stacked group (`blends` only stacked, one per branch); `tint.not_a_group` for a per-channel group or blends on side by side; `tint.animated` for a keyed field. Writes nothing when the grade comes out the same.
  - `tint.removeNodes` (`tint_remove_nodes`): `{ target, nodeIds }`; consumers read the removed node's input, and its `grade.nodes.<id>.*` key tracks go with it.
  - `tint.moveLayer` (`tint_move_layer`): `{ target, nodeId, to }`.
  - `tint.reset` (`tint_reset`): `{ target, tools?, nodeId?, fields? }`; with none of `tools`, `nodeId` and `fields` the whole grade (and every `grade.*` track) goes; with `tools` only the fields those tools own (`logic/tools.ts`, `TOOL_FIELDS`) are cleared, keys included; `nodeId` limits that to one correction, or to every correction inside a group when it is a group's join (`groupOf`) (all tools when none are given); `fields` names top-level value fields to clear beside the tools or alone, and a name that isn't a field of `DEFAULT_CORRECTION` fails with `tint.invalid_grade` before anything is written.
  - `tint.wire` (`tint_wire`, `tint.wire.commands.ts`): Leader Seal's free wiring, `{ target, set: { nodeId, input?, inputs?, r?, g?, b?, keys? }[], add?: { id, node }[] }`. `add` puts nodes in first (ids the caller's own, letters, digits and `_` only as `createId` makes them, else `tint.bad_id`, since a `.` would break a `grade.nodes.<id>.` track path; `tint.node_exists` for a taken one, `"source"` or `"out"`), then each `set` writes the wires of its node's kind (`input` a correction or split, or `nodeId: "out"` for the grade's result; `inputs` a side-by-side or stacked join, whose `blends` stay with their refs and new refs get normal; `r`, `g`, `b` a channel join; `keys` a key join); a field the kind doesn't have is `tint.cant_wire`. Every node id and ref is checked with `Object.hasOwn` (`tint.node_not_found`), a node that would read itself through pictures or keys is `tint.wire_cycle` (project's `gradeReads` from each new read), anything else `validateGrade` refuses is `tint.invalid_grade` (such as a picture ref naming a key join: it has a key, not a picture); then one write, one undo step, nothing when the grade comes out the same. Any valid shape goes: what Baby Seal can't show is sealed, and only that region (`parseStack` reads it again).
  - `tint.placeNodes` (`tint_place_nodes`: an agent lays out the graph as a user can): `{ target, pos: Record<nodeId, { x, y }> }` sets nodes' `pos` in graph units, one undo step, nothing written when no place changes; `tint.node_not_found` for a missing id. `logic/autolayout.ts` `autoLayout(grade)` places the nodes without one (one column per step from the source, the furthest read deciding; rows down each column in `topoOrder`, 150 × 100 units).
  - `tint.setInput` (`tint_set_input`, `tint.color.commands.ts`): `{ clipIds, input }` sets the camera color space (`InputColorSpace`, `INPUT_SPACES`) of clips in one undo step: every clip is read first (`tint.target_not_found`, `tint.not_gradeable`; a composition clip takes only `rec709`, its picture being Rec.709 already: `tint.input_not_for_composition`), then one `ctx.mutate` for all; a clip whose `input` is already the one asked is skipped; `rec709` is the default and is never stored (`minimizeGrade`), so a clip set back to it with no corrections is ungraded again. Nothing is written when no clip changes. `tint_get_grade` returns `input`; `tint_describe` lists the spaces and explains them.
  - `tint.importLut` (`tint_import_lut`, `tint.color.commands.ts`): `{ path }` → `{ lutId }`. Async: the command reads the file itself (`tint.service.ts` `readLut`: the native `tint_read_lut`, then `parseCube`), as `media.import` registers its files, and only then writes `ProjectState.luts[lutId] = { id, name (the file name without extension), path, size }` in one `ctx.mutate` (one undo step); the parsed table goes to `luts.put`, so it isn't read twice. A path already in `luts` returns that LUT's id and writes nothing, so one file has one entry and one texture. Fails with `tint.lut_not_found` (no file) or `tint.bad_lut` (a wrong path, over 8 MB, not UTF-8, not a valid `.cube`; the parser's message). The file stays where it is, kept by path like media.
  - `tint.applyLook` (`tint_apply_look`, `tint.color.commands.ts`): `{ clipIds?, targets?, lookId? , stillId? }` (`targets` any grade targets, both together, each once by `targetsOf`; none is `tint.no_target`), exactly one of the two ids (`tint.look_choice` otherwise; `tint.look_not_found`, `tint.still_not_found`). `logic/look.ts` `addGrade(base, extra, newId)`: a look's corrections go in one after another at the bottom with `insertLayer` (as `tint.addCorrection` does), each named `<look>: <correction>`; a still's whole grade is added after everything the clip has: its nodes under fresh ids (refs renamed through project's `gradeInputs` and `renameGradeKeys`, so every id-bearing field is covered in one place), what read its source reads the clip's result (`grade.out`), its result is the new `out`, `pos` dropped, the clip's color space kept; null (checked with `validateGrade`) is `tint.invalid_grade`. A chain, not a Stacked group: a group's branches don't read each other, so a stack of normal blends would show only the last. Every clip is checked before anything is written, one `ctx.mutate`, one undo step; a still with no grade, or a repeated clip id, adds nothing twice or at all (a no-op writes nothing).
  - `tint.grabStill` (`tint_grab_still`, `tint.still.commands.ts`): `{ at?, name? }` → `{ stillId }`: the grade of the gradeable clip under `at` (default the actor's playhead, in their open composition; `clipUnder`) and a capture of that clip alone, graded (`captureAt(…, { only })`), shrunk to 320 px wide with `@/ui`'s `shrinkDataUrl`, stored as `ProjectState.stills[stillId] = { id, name (default "Still N"), image, grade?, from: { clipId, time } }` and appended to `stillOrder`; one undo step. Fails with `tint.no_composition`, `tint.no_clip`, `preview.capture_failed`. `tint.removeStill` (`tint_remove_still`): `{ stillId }`, `tint.still_not_found`; clips it was applied to keep what they got.
  - `tint.copy` (`tint_copy`, `tint.clipboard.commands.ts`, **not undoable**, never touches the project): `{ target }` puts a copy of the grade on the caller's own clipboard (`TintApi.clipboard`, `createTintClipboard()` in `tint.store.ts`: a map keyed by the command's `ctx.actor`, so the user and each agent have their own, per kernel, never in history); `tint.nothing_to_copy` for an ungraded target. `tint.paste` (`tint_paste`): `{ clipIds?, targets?, tools? }` (as `applyLook`: a group's or composition's grade too, which takes no `input`), `tint.clipboard_empty` when the caller copied nothing. Every clip is checked first (gradeable, `checkedGrade`), all are written in one `ctx.mutate`, one undo step, and a clip that comes out the same is not written. Without `tools` the clip's grade is replaced by a copy (ids kept: a replace sits next to nothing; LUT ids are project-level), every `grade.*` track goes as in `tint.reset`, the clip always keeps its own `input` (camera color space, or none; it belongs to the footage), and a replace that comes out identical writes nothing, so the clip's key tracks stay. With `tools`, `logic/paste.ts` `pastePart` writes the fields `TOOL_FIELDS` gives those tools: the n-th top-level layer takes them from the copy's n-th layer (a field the copy lacks is cleared on the target), and a clip with fewer layers gets new ones at the bottom (`insertLayer`, as `applyLook`) when the copy's layer has something of those tools. **Sealed choice:** only top-level layers are matched, so groups and sealed cards on either side are skipped and nothing is written into one; a limit's shared pick (`limit.from`) names a node of the other grade and is dropped. **Animated choice:** a value field that would change and has keys is refused with `tint.animated` through `refuseUnlessEditable` (as `setCorrection`; a field that would stay the same is fine); opacity and on are never pasted by tools. Paste to all is `paste` with every clip of the strip (the page's button). The strip's Copy, Paste, Paste part (`PastePartMenu`) and Paste to all buttons run these (Copy, Paste and Paste part on the grade of the level shown: the selected clips' own at This clip, else the group's or the timeline's; Paste to all always on every clip's own); no keybindings.
  - `tint.setShotGroup` (`tint_set_shot_group`, `tint.shot.commands.ts`): `{ clipIds, group: { name } | { id } | null }` → `{ groupId? }`. `{ name }` makes a group (`createId("shot")`, `{ id, name }` in `gradeGroups`, no grade yet), `{ id }` moves the clips into an existing one (`tint.target_not_found` otherwise), `null` takes them out. Every clip is checked first (`readGrade`: `tint.target_not_found`, `tint.not_gradeable`); one `ctx.mutate`, one undo step; nothing changes when every clip is already where asked. A group no clip is in any more is deleted with its grade by project's settle (`dropDeletedGrades`), so deleting a group's last clip anywhere removes it in the same step; `gradeGroups` goes when empty. The strip's Make shot group runs it on the selected clips (else the current one) with the name `Shot group <n>` and switches to the Shot group level.
  - `tint.setVersion` (`tint_set_version`, `tint.shot.commands.ts`, logic in `logic/versions.ts` `changeVersions`): `{ clipIds, action: "create" | "switch" | "rename" | "delete", name, to? }`. Versions are per clip (groups and the timeline have none). The active one is the clip's own `grade` and `grade.*` tracks in `clip.animation`, named `gradeVersion` (missing means "A", never stored); the others are `gradeVersions[name] = { grade?, animation? }`. `create` keeps a copy of the showing grade and its `grade.*` tracks under `name` and stays on the showing one; `switch` moves the showing grade and tracks into `gradeVersions[old]` and brings the chosen out (other tracks of the clip stay); `rename` renames `name` (the showing one too) to `to`; `delete` removes a stored version and **refuses the showing one** (`tint.version_active`). A name is 1 to 80 trimmed characters (not `__proto__`: `tint.invalid_name`), unique per clip (`tint.version_exists`; `tint.version_not_found`). Every clip is dry-run on a copy first; one `ctx.mutate`, one undo step; a switch to the showing version or a rename to the same name writes nothing; an empty `gradeVersions` is dropped. The tracks are plain entries of `clip.animation`, so no keyframe helper was needed. A parked version's tracks keep their time because `clipHasKeys(clip)` (project) counts them when trim, split and group maintain `animationOrigin`; a Freeze frame hold keeps each version's grade but not its tracks. Reset, paste and the save-time empty-track cleanup touch only the showing version's tracks.
  - `tint.match` (`tint_match`, `tint.match.commands.ts`, helpers in `tint.match.read.ts`, math in `logic/match.ts` and `logic/chart.ts`): `{ clipIds, kind: "auto" | "white" | "gray" | "shot" | "chart", at?, point?, from?, corners?, nodeId? }` → `{ nodeIds }` by clip, for the clips that changed (a clip whose grade comes out as stored, or whose new correction would hold only defaults, is skipped, as `writeChanged` does; with none left nothing is written). **Async:** each clip is captured alone and ungraded at `at` (default the caller's playhead; a clip that doesn't hold it at its middle; `from` at its middle) through `TintApi.clipFrame` before anything is checked or written; then everything is validated on the state as it is after the captures, and all clips are written in one `ctx.mutate`, one undo step. **Clip level only:** it takes `clipIds` and edits their own grades; a shot group's or the timeline's grade isn't matched (their pictures mix several clips, so "the clip's own picture" has no meaning there); the page turns Match off at those levels. Each kind, all solved on the CPU reference (`applyCorrection`, `evaluatePixel` with the clip's input conversion, LUTs and keyed values at that time) as the forward model, every result clamped into `GRADE_RANGES`: **auto** (pixels spread over the clip's picture, at most ~2400, `frameSamples`): the offset puts the darkest 0.5 % of each channel at 0, then temperature and tint (Newton on two unknowns, `solve2`, Jacobian by finite differences, halved steps, clamped) make the mean's Cb and Cr 0 (gray world); three rounds. **white**: the 3 × 3 mean at `point` (`sourceAt`) comes out neutral, by temperature and tint, then offset's color (x, y; master kept) for what their ranges can't reach. **gray**: the same, offset's color first, then temperature and tint. auto, white and gray write **temperature, tint and offset of the current correction**: `nodeId` (one clip only; the page passes the correction the tools edit), else the first correction of the stack (`currentCorrection`, the one the tools edit with nothing selected, so an agent and the page agree), else a new correction at the bottom; its other values stay and are part of the model; temperature, tint or offset with keys is `tint.animated` (`refuseUnlessEditable`). **shot**: the clip's picture through its whole grade and `from`'s through its own; per channel, mean μ and spread σ of `logish(x)` are matched (`unlogish((lg − μt) σr/σt + μr)`), that mapping fitted by least squares as `g x + o` in display values, written as the gain wheel (`2^n`) and offset (`wheelFor`, the inverse of `wheelChannels`: mean on the master ring, the rest on the puck), and saturation = mean chroma of `from` over the target's after `g x + o` (0…2); a new correction "Match nn" (one past the highest there) at the bottom. **chart**: `corners` (top left at dark skin, top right, bottom right at black, bottom left at white, in frame 0…1, y down); each of the 24 patches (6 × 4, bilinear between the corners, `quadPoint`) is read as the mean of a 3 × 3 grid over the central 40 % of the patch, through what comes before a new correction "Chart" at the top of the stack (before the first item); a least-squares 3 × 3 matrix and offsets (`fitChart`, 4 × 4 normal equations, Gaussian elimination) take them to `CHART_REFERENCE` (BabelColor's sRGB D65 averages of the classic 24-patch chart, as display light for the gamma 2.4 output, `srgbToDisplay`). The matrix goes in the RGB mixer (each cell within −2…2, else refused; keep brightness off); **the mixer has no offsets**, so they go in the same correction's offset wheel, which runs before the mixer: `o = M⁻¹ b`. Fails with `tint.match_input` (white or gray without `point`, shot without `from`, chart without `corners`, `nodeId` with several clips), `tint.target_not_found`, `tint.not_gradeable`, `tint.match_self`, `tint.no_picture` (the point or a patch off the clip's picture, or nothing of the clip in the frame), `tint.chart_too_dark` (mean patch luma under 0.03), `tint.chart_degenerate` (corners enclosing under 0.1 % of the frame, patches too alike to solve, a fitted cell outside −2…2, or a fit missing the patches), `tint.node_not_found`, `tint.animated`, `tint.sealed`, `tint.invalid_grade` or `preview.capture_failed`. Its guards are none stricter than `validateGrade`: balance and shot values are clamped into range; the chart's matrix is never clamped cell by cell: a fitted cell outside the mixer's −2…2 or a root-mean-square miss over 0.1 is `tint.chart_degenerate`. **Balance solves the whole correction as it draws:** `logic/color/evaluate.ts` `correctionInput` gives each pixel's input and key at that correction (the same walk as `evaluatePixel`), and `finishCorrection` (the one place a correction's LUT, opacity and key mix are written, which `evaluatePixel` uses too) takes each candidate's result to what is drawn, so the result is neutral as the grade draws, LUT, opacity and limit included. A clip deleted while being read fails with `tint.target_not_found`.
  - `tint.relinkLut` (`tint_relink_lut`): `{ lutId, path }` points a LUT at another file (read and parsed first), keeping the corrections that use it; `path` and `size` change, one undo step. Fails as `tint.importLut`, and with `tint.lut_not_found` for an unknown id.
  - Read tools: `tint_scopes` (`{ at?, compositionId? }`: captures the graded frame with `captureAt` at `at` (default the agent's playhead in its open composition; pass `at` with another composition; no seek, the time measured comes back as `time`) and measures it with `scopeStats`: r, g, b `{ min, max, mean }` 0 to 255, `clipped.low/high` shares 0 to 1 of pixels at or under 1% / at or over 99% luma, `histogram` 16 luma buckets as shares, `skinDistance` mean degrees from the 123 degree skin line weighted by saturation), `tint_get_grade` (`{ target }`: the layers, numbers, and nodes with full values) and `tint_describe` (fields and defaults, ranges, tools, color spaces, looks, LUTs, and the three levels of grade in order: clip, shot group, whole timeline). Editing tools also include `tint_set_shot_group`.
  - Failures: `tint.target_not_found`, `tint.not_gradeable`, `tint.node_not_found`, `tint.invalid_grade` (the `validateGrade` message; nothing is written), `tint.sealed` (a place inside a sealed card or a move the stack can't show), `tint.animated` (a static write that changes a number that has keys; the message names `keyframe_set` and its path, `at` on `tint_set_correction`, and `keyframe_clear`), `tint.key_not_limited`, `tint.key_cycle`, `tint.key_not_above`, `tint.lut_not_found`, `tint.bad_lut`, `tint.lut_missing` (thrown by the filter in an export), `tint.cant_group`, `tint.not_a_group`, `tint.bad_id`, `tint.node_exists`, `tint.cant_wire`, `tint.wire_cycle`.
- **View commands** (not undoable, not saved, no MCP tools: they are the user's view; `tint.view.commands.ts`): `tint.setMode` (`baby` | `leader`), `tint.pin` (`{ clipId | null }`: makes a gradeable clip of the open composition the one being graded and seeks into it, to where it was last viewed, else its middle; fails with `tint.clip_not_found`), `tint.selectNode`, `tint.setTool`, `tint.setLevel`.
- **Current clip** (`tint.current.ts`, `followCurrent`, registered in `setup` with `onDispose`): the pinned clip until the playhead leaves it (or it is deleted, or another composition opens), else the gradeable clip (`canGrade`, not disabled) under the playhead on the topmost video track that isn't hidden. It follows the playhead without React; `TintApi.current()` and `onCurrent(fn)` read it, and `viewedAt(clipId)` is where the playhead last was inside a clip. Clicking a card in the strip runs `tint.pin`; Ctrl, Cmd or Shift click goes through `TimelineApi.selectClip(id, true)`, so that selection is shared with Edit and shows on the card.

- **Stage 2 notes:** Color mix is folded into the hue curves, so it reads the hue entering the curve step (the hue curves' own input), not the hue after them, and it shares one capped row with each hue curve: Hue vs Hue (hueHue plus every family's hue) totals at most ±180°, Hue vs Saturation (hueSat times every family's sat) at most ×2, Hue vs Brightness at most ×0…×2; past that it clips. `tint_describe` says so too. Color mix's Pick reads the color entering the correction, while mix acts at the curve step. The warper blends neighbouring hue offsets linearly in turns, so two neighbours near ±180° blend through 0. - **Units of a limit** (`tint_describe` returns them as `limitRanges`, `LIMIT_RANGES` in `project`): `color.hue` a pair of degrees 0…360 on the hue curves' circle (red 0, yellow about 72, green 127, cyan 180, blue 252, magenta 307), `[a, b]` with `a > b` wrapping through red, `[0, 360]` every hue; `color.sat` 0…1 of full chroma (0.5); `color.lum` and `brightness.range` 0…1 of luma; `color.soft`, `brightness.soft`, `refine.soft` and `refine.clean` 0…100. - **Stage 3 notes:** a limit's key is read from the correction's input; Show draws the edited correction's key in the live preview only (`view.showPicked`), never in a capture or an export. The CPU and the GPU agree within one 8-bit step for every space and range alone; with a grade after it, a few values (16 in 384 000) of pixels converted far over white (1.8 to 8) and pushed hard by the grade differ by 2 to 4 steps, the half-float picture between passes (the check doc's Stage 5).

- **LUTs** (`logic/cube.ts`): `parseCube(text)` reads `LUT_3D_SIZE` (2…65) or `LUT_1D_SIZE` (2…4096), `DOMAIN_MIN` / `DOMAIN_MAX` (or `LUT_3D_INPUT_RANGE` / `LUT_1D_INPUT_RANGE`), `TITLE`, `#` comments (whole lines or after a value), skips other uppercase keywords (`LUT_IN_VIDEO_RANGE`, …), refuses a combined 1D shaper + 3D file (Resolve's form) with a message saying to export a single 3D LUT, and throws an `Error` saying what is wrong; `lookupCube` / `applyCube(rgb, lut, strength)` is the CPU reference: `t = clamp((c − min) / (max − min), 0, 1)` per channel (light over 1 reaches this step, so the clamp is needed), the table read at `t · (N − 1)`, trilinear between the eight nearest entries of a 3D table and linear per channel in a 1D one, then mixed toward by strength. It is the last step of a correction, after Creative and before the limit and opacity mix (`evaluatePixel`). On the GPU (`correct.glsl.ts`) the same step reads the texture at the texel centers `(t · (N − 1) + 0.5) / N`, which is what linear filtering makes trilinear; a 3D LUT is a half-float `sampler3D` (`textures.ts` `bakeLut`, red along x, green y, blue z as `.cube` orders it), a 1D one a one-row `sampler2D`, each its own program (`tint.correct.lut3d`, `.lut1d`, and the `.keyed` ones) so no sampler of another type shares a unit; with no LUT, strength 0 or a LUT not read, the plain program runs, unchanged. A LUT texture is keyed `tint.lut:<id>`, its version a hash of the file's text, baked again only when the file changes. Parity: within one 8-bit step for 3D 17, 33, 65, 1D, a custom domain and strength 0.5, alone and after a grade (`docs/superpowers/specs/2026-11-03-tint-webgl-check.md`, Stage 5).

- **Keyframes** (`tint.keys.ts`, contributed to `keyframe`'s `keyTargets` as `tint.keys`): a clip on a video track with its own grade can key, for each correction, every number of `KEYABLE_VALUES` at `grade.nodes.<id>.values.<path>` (`saturation`, `lift.x`, `zones.z2.at`, `creative.vignette.amount`, …) and `grade.nodes.<id>.opacity`, labeled `<nn> <name> · <Field>` (`01 Correction · Lift x`), `blend: "number"`, `shared`, ranges from `GRADE_RANGES`; `read` is `correctionOf` of the clip as keyed; `commitStatic` is `tint.setCorrection` (a wheel or group written whole with that one number changed). The keyable set is every number of `GRADE_RANGES` that reaches the shader as a uniform: Color mix (`mix.*`) and the warper (`warper.*`) are left out because they are baked into tables (`textures.ts`), which a keyed value would bake again every frame, and the mixer is a matrix; curves, booleans, limits and LUTs aren't numbers to key. Shot group and whole-timeline grades have no keys. `tint_describe` lists the set as `keyable`. **Reaching every reader:** the keys are tracks in `clip.animation`, so `animatedClip` writes them into the clip's grade; the preview, captures, thumbnails and export already draw the clip `resolveFrame` gives (`animatedClip` at the frame's time), and `pickColor` and Match read `animatedClip` at their time, so nothing in the filter changed. Per frame only uniforms change; the table caches see the same curves, mix and warper and never re-bake. **Editing:** `tint.setCorrection` takes `at` (a timeline time, clip grades only): each keyed number the patch changes from its value at `at` gets a key there (`keyframe.set`, nested, so one undo step) and goes back to its stored value in the patch, which then writes as usual (`tint.key.patch.ts`). Without `at`, a patch may hold a keyed number only at its stored value (`animatedFields`' `same`), so a wheel can be written whole around a keyed component. `useLiveEdit` commits with `at` = the playhead at the clip level, so a drag or a typed value on a keyed number becomes a key on release (Escape still cancels), and `useEditTarget` shows the values at the playhead (`useClipAtPlayhead`). **The diamond:** `ToolHeader` draws `KeyAction` on a clip's own correction only (not a group, a shot group or the timeline) for the open tool's changed numbers (`changedKeyPaths`: of `toolKeyPaths`, under the fields `TOOL_FIELDS` gives the tool, those whose value at the playhead differs from `DEFAULT_CORRECTION`, plus those already keyed); it keys them together at the playhead (`keyframe.setMany`, one step) or removes the keys there. With nothing changed and nothing keyed it is disabled, with the tip "Change a value to key it". **Known gaps:** opacity has no diamond on the page (key it from the keyframe panel or `keyframe_set`), and the layer row's opacity scrub shows the static value, not the keyed one (a scrub on keyed opacity still keys it, through `at`); the Wheels diamond covers the wheels only, not the Basics sliders beside them (temperature, tint, contrast, pivot, saturation, hue: Basics owns them, so its diamond keys them). A static write that leaves a keyed number (opacity too) at its stored value is no refusal.
