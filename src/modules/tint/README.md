# tint

The Tint page, a tab between Edit and Sound, where colors are graded: corrections stored once as a graph, shown as layers (**Baby Seal**) or as nodes (**Leader Seal**), with Basics, wheels, curves, Color mix, Warper, Creative, limits, LUTs, Match and the RGB mixer, scopes beside them and the clips below. **The frame, the layer list, Basics, the wheels (Primary, Log, Bars, Zones), the curves, Color mix, the Warper, Creative, Limit and the RGB mixer are real; LUT and color and Match are still demo data**: the viewer (the preview's own stage, so it plays), the clip strip, the current clip and the seal switch read the open project; the layer list (Baby Seal) reads and edits the current clip's real grade; Basics, the wheels, Curves, Color mix, the Warper, Creative, Limit and the RGB mixer edit the selected layer (else the first correction; with none yet, the first edit adds one); the node graph and the other tools are still drawn from demo data (`ui/demo/`) and edit nothing yet. A clip's saved grade already draws (every value of a correction but its LUT and shared key: Basics, all the wheels, the curves, Color mix, the warper, skin pull, the mixer, Creative and its limit by color and brightness) in the preview, captures and export through the `tint.grade` filter. The design is `docs/superpowers/specs/2026-11-03-tint-page-design.md`, the plan `docs/superpowers/plans/2026-11-03-tint.md`, the picture `docs/prototype/designs/tint-d-studio.html`.

- **Tier:** feature
- **Requires:** `project` (grade types and helpers, the strip), `preview` (the picture filter, `redraw`, playback, `gpuAvailable`, `PreviewStage`), `timeline` (the selection), `media` (probes for the strip's cards)
- **Contributes:** picture filter `tint.grade` (`pictureFilters`, order 100, `tint.filter.ts`): applies to a clip with a grade that `canGrade`; its passes are `gradePasses(clip.grade, live, textures, aspect)` (`aspect` from the filter's `size`, for the vignette), so a grade shows in the preview, captures and export; live values are laid over it only when `target` is `"preview"`, so a capture or an export draws the saved document even mid-drag; so is Limit's Show (`view.showPicked`, passed as `gradePasses`' `show`), which never reaches a capture or an export. One per kernel (`createTintFilter(live, view)`), since it reads that kernel's live values and view (`redrawOnShow` redraws the preview when `showPicked` changes), with its own lookup tables (`createGradeTextures`); page `tint.page` (`TINT_PAGE`; `appPages`, icon `Palette`); top bar item `tint.sealSwitch` (`topBarItems`, right: Baby Seal | Leader Seal; `topBarItems` has no page filter, so `SealSwitch` reads `pagesRef` and renders nothing unless the Tint page is open); keybindings `tint.previousClip` and `tint.nextClip` (Up, Down; only on the Tint page; `tint.keys.ts`); the page has `keepsPlayback`, so Space plays and pauses on it
- **Commands** (all undoable; a `target` is `{ clipId }`, `{ groupId }` (a shot group) or `{ compositionId }`; each reads the grade, edits a copy with `logic/stack*.ts`, runs `minimizeGrade` and `validateGrade`, then writes once):
  - `tint.addCorrection` (`tint_add_correction`): `{ target, at?, values?, limit?, name? }` adds a layer (default: the bottom of the stack) and returns `{ nodeId }`.
  - `tint.setCorrection` (`tint_set_correction`): `{ target, nodeId, patch: { values?, limit? (null removes), opacity?, on?, name? } }`; each given value field replaces that field whole.
  - `tint.removeNodes` (`tint_remove_nodes`): `{ target, nodeIds }`; consumers read the removed node's input, and its `grade.nodes.<id>.*` key tracks go with it.
  - `tint.moveLayer` (`tint_move_layer`): `{ target, nodeId, to }`.
  - `tint.reset` (`tint_reset`): `{ target, tools?, nodeId?, fields? }`; with none of `tools`, `nodeId` and `fields` the whole grade (and every `grade.*` track) goes; with `tools` only the fields those tools own (`logic/tools.ts`, `TOOL_FIELDS`) are cleared, keys included; `nodeId` limits that to one correction (all tools when none are given); `fields` names top-level value fields to clear beside the tools or alone, and a name that isn't a field of `DEFAULT_CORRECTION` fails with `tint.invalid_grade` before anything is written.
  - Read tools: `tint_scopes` (`{ at?, compositionId? }`: captures the graded frame with `captureAt` at `at` (default the agent's playhead in its open composition; pass `at` with another composition; no seek, the time measured comes back as `time`) and measures it with `scopeStats`: r, g, b `{ min, max, mean }` 0 to 255, `clipped.low/high` shares 0 to 1 of pixels at or under 1% / at or over 99% luma, `histogram` 16 luma buckets as shares, `skinDistance` mean degrees from the 123 degree skin line weighted by saturation), `tint_get_grade` (`{ target }`: the layers, numbers, and nodes with full values) and `tint_describe` (fields and defaults, ranges, tools, color spaces, looks, LUTs).
  - Failures: `tint.target_not_found`, `tint.not_gradeable`, `tint.node_not_found`, `tint.invalid_grade` (the `validateGrade` message; nothing is written), `tint.sealed` (a place inside a sealed card or a move the stack can't show), `tint.animated` (a static write to a field that has keys; the key path comes later).
- **View commands** (not undoable, not saved, no MCP tools: they are the user's view; `tint.view.commands.ts`): `tint.setMode` (`baby` | `leader`), `tint.pin` (`{ clipId | null }`: makes a gradeable clip of the open composition the one being graded and seeks into it, to where it was last viewed, else its middle; fails with `tint.clip_not_found`), `tint.selectNode`, `tint.setTool`, `tint.setLevel`.
- **Current clip** (`tint.current.ts`, `followCurrent`, registered in `setup` with `onDispose`): the pinned clip until the playhead leaves it (or it is deleted, or another composition opens), else the gradeable clip (`canGrade`, not disabled) under the playhead on the topmost video track that isn't hidden. It follows the playhead without React; `TintApi.current()` and `onCurrent(fn)` read it, and `viewedAt(clipId)` is where the playhead last was inside a clip. Clicking a card in the strip runs `tint.pin`; Ctrl, Cmd or Shift click goes through `TimelineApi.selectClip(id, true)`, so that selection is shared with Edit and shows on the card.
- **Points it owns:** none yet (`tintLooks` comes with looks)
- **API** (`TintApi`, per kernel): `pickColor(clipId, nodeId, point)` (the one way pickers read a color, `tint.pick.ts` `createPicker`: captures the clip alone and ungraded at the playhead, kept inside the clip, with `captureAt(…, { only, bypassFilters: true })`, decodes it (`tint.pixels.ts` `pixelsOf`, shared with `tint_scopes`) and reads the point (0…1 of the viewer's frame, y down) through the corrections before `nodeId` with `logic/pick.ts` `pickAt`: a 3 × 3 mean, then `evaluatePixel(…, stopAt: nodeId)`; `nodeId` null runs the whole grade. The capture has the clip where the viewer shows it, so the point is read as clicked; `clipPlacement` (the keyed transform and, for a file, the probed size) says whether it is on the clip's picture (null when not) and gives `at` in the picture (`pictureAt`); a clip whose size isn't known (a composition inside another) skips that test. Rejects as `captureAt` does), `thumb(clipId, nodeId, time, compositionId)` (a data URL of the clip alone with its grade cut at that node: `PreviewApi.captureAt(…, { only, filters: { "tint.cut": nodeId } })`: the cut is that one capture's own option, read by `tint.grade` as `info.options` (`TINT_CUT`), never shared state; queued one at a time), `live` (`TintLive`: `get(clipId)`, `set(clipId, LiveGrade | null)`, `subscribe(fn)`; values being dragged, by node (`Partial<CorrectionValues>`, `opacity`, `on`), laid over the saved grade by the filter; each `set` asks `preview.redraw()`; never in history), `available` (a getter: `PreviewApi.gpuAvailable()`, whether WebGL2 works; when false the page shows `TintUnavailable` instead of the page), `current()`, `onCurrent(fn)`, `viewedAt(clipId)`, `view` (`TintView`: the seal mode, the pinned clip, the open tool, the wheels mode, the grade level, the scope, the curve, the left tab, the selected layer, the Color mix family, the viewer toggles, a color pick (`picking`, `picked`: the color the edited correction reads there; Curves' Pick hue, Color mix's Pick and Limit's droppers) and Limit's Show (`showPicked`, a correction id); never in history)

  - `tint.store.ts`: `createTintView()`, `createTintLive(redraw)`. `tint.filter.ts`: `createTintFilter(live)`, `TINT_GRADE_FILTER`. `tint.layout.ts`: `TINT_LAYOUT`, the page's sizes from the mockup. `tint.types.ts`: every type.

  - `logic/` (the grade as layers, pure): `order.ts` (`topoOrder`, depth first from `out` so a chain reads top to bottom; `gradeGraph`, the nodes on a picture path from source to out; `postDominators`), `shape.ts` (`pairOf`: one step between a vertex and its immediate post-dominator, read as a layer, a side-by-side or stacked group, a per-channel group, or nothing), `seal.ts` (`parseStack`, `sealedRegions`), `stack.ts` (`toStack`, `numberOf`, `emptyGrade`), `stack.edit.ts` (`insertLayer`, `moveLayer`, `removeNodes`), `stack.group.ts` (`groupLayers`, `ungroup`), `rewire.ts` (ref rewiring and stack positions). Stack order: top is closest to the source; numbers `"01"`… in stack order, depth first, a sealed card's corrections included. A step that isn't a layer or a recognized group is **sealed**, and so are keys the stack can't show (a key join, a pick off the picture path, a pick from a sibling branch): the steps holding every correction of such a key are sealed together (`"sealed:<first node>"`). A shared key from a correction above is not sealed ("Uses the pick of 03"). Nodes off the picture path and not used as keys aren't shown. Every edit returns a new grade; `moveLayer` and `groupLayers` return null for what Baby Seal can't do (into or out of a sealed card, a group into itself, an invalid result). A list's last item exits with the ref its sink reads, channel included, so an edit there keeps a split's channel; a slot whose picture is a whole split (read through several channels) takes no edit. `ungroup` also points off-path readers of the join at the last branch's end, and readers of the split at the group's input.
  - `logic/color/` (the color math, the CPU reference; values are display-referred Rec.709, 0…1 in range, never clamped between steps): `basics.ts` (every constant the shader shares, the Rec.709 transfer, the log-ish space of contrast, `whiteBalance`, tone bands, rolloff (0…100: values above `1 - rolloff / 200` eased toward 1), `toYcc` / `fromYcc`, `skinWeight` (the skin line at 123°, full within 15°, gone past 35° and under 0.02…0.06 of chroma; protect skin and skin pull share it), `pullSkin` (skin pull 0…100 turns a skin hue toward the line by up to `SKIN_PULL_REACH` 0.75 of the way, times its weight, chroma and luma kept); the formulas chosen are written at its top), `wheels.ts` (the primary wheels: a puck's reach toward each channel's hue, red at the top and clockwise, `y` down as `ColorWheel` draws it; faded film `f = fade / 100`: chroma × `1 - 0.25 f`, then each channel lifted by `0.18 f (1 - clamp(c))²`; the vignette over the clip's own picture (`PixelAt`, `vignetteWeight`): `d = (|qx|^n + |qy|^n)^(1/n)` from the middle, an ellipse fitting the picture at roundness 0, a circle fitting its short side at +100, a rounded rectangle (`n` up to 8) at -100, weighted by `smoothstep` around `0.4 + 0.8 midpoint / 100` over `0.05 + feather / 100`; amount below 0 darkens `c (1 + a w)`, above 0 lightens `c + (1 - c) a w`), `mixer.ts` (`mixerOf`: rows out, columns in; keep brightness scales the matrix by `1 / (LUMA · row sums)` so grays keep their luma, only when that sum is at least `KEEP_FLOOR` 0.05 (below it or negative the matrix is used unscaled, so it never blows out or inverts the picture); monochrome puts the luma of the mixed color in all three; identity and not monochrome is no step), `correct.ts` (`prepareCorrection`, what a correction's values come to for every pixel, the shader's uniforms, the curve table when the curves or Color mix change anything and the warp table when the warper moves anything; `applyCorrection`; `correctPixel`, in the spec's order: exposure and white balance, the primary wheels then the log and zone wheels, contrast, tone bands, rolloff, curves with Color mix, the warper, saturation, vibrance and hue with protect skin, skin pull, the RGB mixer, Creative (split toning, faded film, vignette); every step at its defaults is skipped, null or 0 in `CorrectionParams`), `curves.apply.ts` (the curve step: `sampleCurves(curves, mix?)`, 8 rows (`CURVE_ROWS`: Y, R, G, B, hueHue, hueSat, hueLum, lumSat) of 1024 samples rounded to half-floats (`half`), exactly what the texture holds, Color mix's curves folded into the hue rows (offsets added on Hue vs Hue and Hue vs Brightness, scales multiplied on Hue vs Saturation); `curveAt` reads a row linearly as the texture does; `curvesActive`, so curves at their defaults add no work; `hueOf` / `cbcrHue`, the hue in CbCr from red (`HUE_ZERO`) in turns; `applyCurves`: custom `out = R(Y(in))`, slope 1 outside 0…1; Hue vs Hue turns by `(v - 0.5)` of a turn, Hue vs Saturation and Brightness vs Saturation scale chroma by `2v`, Hue vs Brightness scales luma by `1 + (2v - 1)·min(chroma / 0.5, 1)`; formulas at its top), `mix.ts` (Color mix as hue curves, no step of its own: `FAMILY_HUES` (each family at the hue of the full color of HSV 0°, 30°, 60°, 120°, 180°, 225°, 270°, 315°: reds 0, oranges 0.099, yellows 0.2, greens 0.352, aquas 0.5, blues 0.654, purples 0.783, magentas 0.883), `mixToHueCurves` (a point per family, hue ±100 = ±30°, sat ±100 = chroma ×0 to ×2, lum ±100 = luma ×0.5 to ×1.5, and a point between each two families, neutral at range 0 and their mean at 100), `mixActive`, `nearestFamily`, `withFamily`, and `curveStepActive` / `sampleCurveStep`: the curve step of a correction, its curves with Color mix folded in), `warper.ts` (the warp step: grid point `index = ring · 12 + spoke`, spoke `k` at hue `k / 12` (the curves' hue), ring 0, 1, 2 at strength 1/3, 2/3, 1 (1 = chroma 0.5), the center fixed; - **Stage 2 notes:** Color mix is folded into the hue curves, so it reads the hue entering the curve step (the hue curves' own input), not the hue after them, and it shares one capped row with each hue curve: Hue vs Hue (hueHue plus every family's hue) totals at most ±180°, Hue vs Saturation (hueSat times every family's sat) at most ×2, Hue vs Brightness at most ×0…×2; past that it clips. `tint_describe` says so too. Color mix's Pick reads the color entering the correction, while mix acts at the curve step. The warper blends neighbouring hue offsets linearly in turns, so two neighbours near ±180° blend through 0. The Warper's header reset clears its points, pins and smoothing; its own Reset clears points only. Skin pull has no control yet (Match, later); Basics shows Rolloff and Protect skin. A chain of corrections differs more between the CPU and the GPU than one correction does: the picture between passes is kept in half-floats, so a steep curve later in a chain can make 2 to 4 steps on a pixel (the check doc's Stage 2).
- **Units of a limit** (`tint_describe` returns them as `limitRanges`, `LIMIT_RANGES` in `project`): `color.hue` a pair of degrees 0…360 on the hue curves' circle (red 0, yellow about 72, green 127, cyan 180, blue 252, magenta 307), `[a, b]` with `a > b` wrapping through red, `[0, 360]` every hue; `color.sat` 0…1 of full chroma (0.5); `color.lum` and `brightness.range` 0…1 of luma; `color.soft`, `brightness.soft`, `refine.soft` and `refine.clean` 0…100. Saturation, `lum` and `range` pairs never run backwards.
