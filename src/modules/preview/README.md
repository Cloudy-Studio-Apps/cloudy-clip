# preview

Playback and the preview: the playhead, the engine that draws the timeline at the playhead, the
viewer (zoom and pan around the frame) and the preview panel with its transport bar.

- **Tier:** core
- **Requires:** `project`, `element` (how each kind of clip is drawn), `junction` (how the two
  clips of a junction are mixed), `media`, `fonts`
- **Speed:** an element plays at its clip's rate (`syncSlot` sets it each time, since loading a file resets it, and a released slot goes back to 1), and drift limits scale with the rate. A ramped clip plays at `rateAt(clip, time)` (`project`), set only when it moved by more than 0.01, its element is placed by `sourceTimeAt`, drift limits follow that rate, and a speed drag (`previewProps`) doesn't reach it. A clip without pitch correction gets the shift through the pitch worklet (`createSoundAtSpeed`), following the rate in 0.01 steps (each rate keeps its own sound object). A reversed clip plays `reversedUrl`; until that copy is ready the clip is left out of the frame and `whenReversed` asks for a redraw. `elementUrl` (`engine.audio.ts`) picks the file: a clip on an audio track heard through noise reduction (`project`'s `heardDenoise`: the top-level track's, else the master's; inside a placement, the outer track's, carried in `Nesting.denoise`; a clip about to start finds its top-level track from the first segment of its path) plays `denoisedUrl`, its rendered file (a reversed clip its reversed copy), and until that's ready what it would play without, so it never goes quiet. The engine never starts a rendering: `sound` does. A held frame stays paused.
- **Keys and paths:** `resolveFrame` puts `followedClip(clip, time, project.paths)` (`project`: `animatedClip`, then a follower moved onto its motion path) in each active clip, and the same at `clip.start` in each upcoming one, so the engine draws keyed values with no other change. A placement's inner frame is still found from the saved clip.
- **Disabled clips** are left out of `resolveFrame`; a junction beside one isn't active.
- **Contributes:** panel `preview.panel` (main); overlay `preview.fieldGuide` (`previewOverlays`: the field guide and corner marks, DOM only, so never in a capture or export); keybindings `preview.toggle-play` (Space),
  `preview.seek-start` (Home). Playback pauses when another page covers the editor
- **Points it owns:** `previewOverlays` (`preview.points.ts`): layers drawn over the frame, sized
  and moved with it, positioned in % of the frame (`transform` contributes its selection box). Each overlay's
  wrapper ignores the pointer (`pointer-events-none`); an overlay turns it back on for the parts
  that take input, so overlays stacked later never block the ones below.
  `pictureFilters` and `frameFilters` (`preview.points.ts`, keyed by `id`): GPU passes a feature
  contributes (`tint`'s grades). A `PictureFilter` (`{ id, order, applies(clip, project, options?),
ready?(clip, project), passes(info) }`) changes a clip's own picture before it lands, so a grade
  scales, blends and fades with it: a video frame after its levels pass, a cached image, a
  placement's canvas. Clips that draw themselves (text, solids, stickers) are not filtered. A
  `FrameFilter` (the same, over a `Composition`) changes a composition's composed frame: the top
  level after every track is drawn, and inside each placement before the placement's own picture
  filters. `info` (`FilterInfo`): the clip as drawn (keyed values now; a filter merges its own live
  values), the project, the `path`, the `size` the passes run at, the composition's `time` and
  `target` (`"preview"`, `"capture"`, `"export"`); a frame filter gets `composition` instead of
  `clip` and `path` `""` at the top; both are asked `applies` with the capture's options. Filters run in `order`; each one's input -1 is the picture so
  far and n its own pass n (`logic/chain.ts` `chainPasses` renumbers them; exported, so a filter can run several grades in a row), and a picture's levels
  and every filter run in one `run`, one upload. `ready` false holds the frame like an undecoded
  video (`logic/readiness.ts` `filtersReady`: every applying filter is asked). **Errors:** a filter
  whose `passes` throws, or whose passes the GPU fails on (or no WebGL2): in the live preview the
  picture draws without it (the levels pass alone is tried again) and the user is told once per
  kernel per filter id (`preview.filters.ts`); in a capture or an export the frame rejects with
  that message, so `captureAt` and the export fail and say why (an export never silently drops a
  grade). The module sorts the contributions by `order` only when they change, and redraws then.
- **API** (`PreviewApi`, per kernel): `playback` (the user's clock), `clockFor(actor)` / `dropClock` (each collaborator has a `logic/virtual.clock.ts` playhead: wall-clock time read on demand, no frames, nothing drawn; commands use `clockFor(ctx.actor)` so an agent never moves the user), `attachCanvas` (canvases stack: the kernel's one engine is made on the first canvas and draws on the newest attached only, through `PreviewEngine.setCanvas`; when that one detaches, the one under it is drawn on again, so the Sound page's small stage and the editor's never draw at once. The engine, its media elements and its sound graph stay across the switch, so playback has no gap and the loudness keeps counting; the engine goes only when no canvas is left), `redraw`, `scrub(time)` / `isScrubbing()` / `onScrubbingChange(listener)` / `holdScrub()` (silences scrub until released, cutting a slice under way; `sound` holds it while a take records) (audio scrub, `preview.scrub.ts`: a slice plays 80 ms of sound from `time` through the same graph as playback, so it is mixed, metered and sounds like playback, pitch, speed and reverse included; `PreviewEngine.playSlice` seeks every element exactly there while paused, then plays it, and never reaches the loudness reading (the tap stays off inside `playSlice`, no on/off toggle); a slice that throws is logged; calls during a slice wait and only the latest plays next, so a fast drag never piles slices up; while a slice plays, redraws go on from where it has got to, and the last slice ending pauses media and redraws the paused frame; nothing while playing; the timeline's ruler scrub calls it on each move, and the Sound page's meters run while a slice sounds),
  `captureAt(time, compositionId, { bypassFilters?, only?, filters? })` (`filters`: values for filters keyed `<module>.<name>`, handed to every picture and frame filter as `FilterInfo.options` for this one capture only: `setPicture` sets them on the capture engine's `EngineFilters.captureOptions`, and the live engine and `createRenderer` never get any) (filters applied unless `bypassFilters`; `only` draws that top-level clip alone over the background, for a clip's own picture: no junction mix with the clip beside it, at Normal with its opacity, its picture filters and the composition's frame filters still running unless `bypassFilters`; `preview.capture.ts`: its own picture-only engine on a detached canvas, polled with timers because frames stop on a hidden window, disposed after 30 s idle; never touches the user's preview; an undecoded frame is an error, not a stale picture; checked on WebKitGTK with the window on another workspace, 45 s hidden, 16 of 16 exact frames; `document.hidden` stayed false there, so nothing may depend on visibility events; not checked on WebView2), `createRenderer({ project, compositionId, mediaUrl? })` (`preview.capture.ts`: a hidden picture-only engine at the composition's full size; `frameAt(time)` waits up to 30 s for every layer and returns RGBA bytes read with `getImageData`, which is what export sends to FFmpeg; the canvas keeps the same 2D context, never `willReadFrequently`; `project` is a snapshot, so later edits don't reach it), `videoLevels()` (`preview.levels.ts`: what the canvas holds for video black and white, measured by `createVideoLevelsMeter` once per kind of color tags (`ProbeMeta.colorTags`) on `media.levelsClip(tags)` with `measureVideoLevels`; `videoLevels()` measures every kind among the files imported. A kind is null when within 6 of 0 and 255, a reading with black above 64 or white below 192 is refused as undecoded, and a failure rejects and is tried again on the next ask. WebKitGTK (GStreamer) expands the range of some kinds and not others, whatever the picture size, measured live: a file that states a matrix but leaves primaries or transfer unstated (`tv/bt709/unknown/unknown`, `tv/bt470bg/unknown/unknown`, what FFmpeg writes for `-colorspace` alone) is drawn squeezed, black at 16 and white at 235, while fully tagged (`tv/bt709/bt709/bt709`, `tv/smpte170m/smpte170m/smpte170m`) and untagged files are drawn right; a full-range file stating every tag draws right, one with no other tag is drawn as video range, which no levels pass can undo. So each video layer, in the live preview, captures and renderers alike, gets the GPU levels pass (`gpu/gpu.levels.ts`, rounding to 8-bit steps like the table it replaced) of its own file's kind: engines ask `videoLevels(mediaId)` at each frame, and asking starts that kind's first measure. A kind not measured yet, not measurable (no FFmpeg, odd tags, a failed measure) or of a file not probed draws as the webview gives it: expanding a picture that is already right crushes its blacks and whites for good, while a squeezed one only looks flat. The live preview redraws when a kind turns out squeezed; `captureAt` and `frameAt` first wait for the first measure of every kind imported to end, either way (`settled(tags)`: a failure is retried only by asking `videoLevels()` again, never per frame). Without WebGL2, video draws as it is), `gpuAvailable()` (whether WebGL2 works here, asked once per kernel with a throwaway runner; the Tint page shows its unavailable panel when false), `previewTransform(clipId, transform | null)` (draws a live transform during a
  canvas gesture without changing the project), `previewProps(clipId, patch | null)`
  (a live patch of any element's values drawn over the saved ones until cleared; groups may be
  partial; a `transform` patch moves any picture, media included), `onPropsOverride(listener)` (fires on set/clear) and `propsOverride(clipId)` (so the
  canvas tools measure the picture being drawn), `viewport` (`store`, `zoomBy`, `panBy`, `fit`), `picture` (`PreviewPictureApi`, `preview.picture.ts`, ephemeral, the live preview only: `view` (a store of `{ bypass, compare, viewer }`), `setBypass(on)` (no filters), `setCompare(wipe | null)` (0…1, clamped: the frame is drawn with filters, then again without them, clipped left of `wipe × width`; the video is drawn twice), `setViewerPasses(id, passes | null)` (passes run last over the whole live canvas, after compare, in the order set; a failure is reported once by `id`), `onFrame(listener)` (after each live draw) and `readFrame(maxWidth)` (the live canvas drawn scaled down on a small canvas of its own, `willReadFrequently`, and read with `getImageData`; the live canvas itself never is; null without one). None of these reach captures or `createRenderer`: the controller hands them to the live engine through `PreviewEngine.setPicture`; a capture sets only its own `bypass` and `only`),
  `sound` (`PreviewSound`, `preview.sound.ts`, ephemeral, never in the document or an export: `previewMix(trackId | busId | "master", patch | null)` plays a live `LiveMixPatch` (`Partial<TrackMix>`, and the master's `trimDb`) over the saved mix until cleared (on a group, its `volumeDb` and `effects`), for a fader or pan drag that commits one `sound.*` command on release (a patch with `effects` plays a whole live chain: the Channel tab sends the chain with the dragged effect's new values; the same kinds, order and ids only update the nodes, nothing is rebuilt); `setSolo(trackIds)` (none means all sound); `setMonitor({ mono, dim, speakerDb })` (`DEFAULT_MONITOR` is stereo, not dimmed, 0 dB); `levels()` gives `MixLevels`, the instantaneous peak of each track bus, each group bus (by its id, in `tracks`) and the master in dBFS (`-Infinity` for silence), with no peak hold, for a caller to read per frame; `reduction(target)` gives how far the compressors on a track, group (by its id) or the master turn the sound down now, in dB (0 or more, 0 when it has none, they're off or nothing plays), the sum over the strip's compressors of what their worklets last posted (about 30 times a second, the peak since the previous post, only when it changed; the engine keeps the latest in a field, so nothing is allocated per message or per read), read once a frame by a caller, never as React state; `spectrum(into)` fills a `Float32Array` of `SPECTRUM_BINS` (1024) with the master's spectrum in dB per bin (the louder of the two sides, `-Infinity` for silence; bin `i` at `i * rate / (2 * SPECTRUM_BINS)` Hz) and returns the context's sample rate (0 without a graph), reading the master meter's two analysers (no analyser of its own; `Meter.spectrum`), allocation-free, for a caller's own per-frame loop; `loudness()` gives the `LoudnessReading` of the master, measured only while playing, since the last `resetLoudness()` (paused, the last reading stands) (momentary and short-term LUFS, gated integrated LUFS, range in LU, true peak in dBTP, the maximum since the last reset, which never falls back, and `correlation`, left against right over the last 400 ms, −1 to 1, 1 for silence or one side silent: the worklet's meter sums l·r, l·l and r·r per 100 ms step beside the loudness), `-Infinity` where a window hasn't filled, and null until the worklet has posted its first reading, or for good if it couldn't load). Each change makes a new `LiveSound` handed to the engine at once (`PreviewEngine.setSound`), and to a newly attached engine
- **Files:**
  - `preview.clock.ts`: the playhead, driven by `requestAnimationFrame`; listeners are called per
    frame without React. It holds the loop region (`getLoop`, `setLoop(range | null)`; `sound` turns it off while a take records and sets it again after, so a take never wraps,
    `onLoopChange`): ends put in order and clamped to the composition, under one frame
    (`frameDuration` of the open composition) refused (`setLoop` returns false). Playing,
    crossing `to` goes back to `from`; playing from past `to` plays on; setting a loop mid-play
    counts from there (`logic/loop.ts`: `fitLoop`, `loopTime`). An agent's clock (`logic/virtual.clock.ts`) never loops: its loop members are inert.
    The loop is view state, set by the UI through `preview.setLoop` on the user's clock: never in
    the project or history, and no MCP tool (an agent's clock plays nothing). A loop left past a
    shortened composition is clamped, or cleared when under a frame is left; the module does
    this (and keeps the playhead inside) on every project change, with or without a preview on
    screen.
  - `gpu/`: the GPU runner (`createGpuRunner`, `gpu.runner.ts`): one WebGL2 context per engine,
    made the first time it is needed (live, each capture engine, each renderer; passed in
    `EngineOptions.gpu` and disposed with the engine). The only place in the app that creates a
    WebGL context. `run(source, size, passes)` uploads the source once (8-bit, not premultiplied, no
    color-space conversion), runs `GpuPass`es in order (input -1 is the source, n the output of pass
    n, as `u_in0`, `u_in1`…) on targets pooled by size and format (`gpu.targets.ts`: `RGBA16F` with
    `EXT_color_buffer_float`, else `RGBA8`; at most 8 free kept), the last one on its canvas, which
    the caller draws before the next `run`. Targets go back to the pool in a `finally`. Uniforms: a
    number is a `float`, 2–4 numbers a `vec`, `gpuInt(…)` an `int`. Data textures
    (`GpuTexture`, `gpu.textures.ts`: `"1d"` as one row, `"2d"`, `"3d"`; bytes `RGBA8`, floats
    `RGBA16F`) are kept by key and uploaded again only when `version` changes, at most 256 (`KEPT`): after each run (`trim`, never during one, so nothing a run binds goes while it draws) the least recently bound past the cap are deleted, and a key that comes back is uploaded again; 256 holds many frames' worth of visible clips × corrections × tables; they take the units
    after the inputs. A new target is made on unit 0 (bound to the input right after), so a sampler
    a pass leaves unbound never points at the target being drawn, and after each draw the units
    from 1 up that the pass used are emptied (`unbindUnits`): a sampler of a shared program keeps
    the unit it was last set to, so a pooled target left bound there as a pass's second input could
    come back as a later pass's output while that sampler still reads it (a feedback loop, and WebGL
    drops the draw); the `finally` empties them too, so a pass that throws leaves no released target bound. A lost context
    (`webglcontextlost`) is made again on the next `run`; if that fails, `available` is false for good
    and `run` throws `GpuUnavailable` (`gpu.errors.ts`), as it does without WebGL2. `gpu.levels.ts`:
    `levelsPass(levels)`. `gpu.blend.ts`: `BLEND_GLSL`, `vec3 blend(int mode, vec3 base, vec3 top)`
    with modes numbered in `BLEND_MODES` order (W3C formulas, as the canvas), for a filter's own
    fragment (`tint`'s stacked groups call it; its CPU twin is `tint`'s `logic/color/blend.ts`). A
    pass may read any number of earlier outputs (`tint`'s joins read a group's entry and every
    branch); programs are kept by pass key and input count (`gpu.programs.ts`). The engine sends a video
    frame through the levels pass once per draw (a playing video can move on between two draws). The
    live engine (`EngineOptions.capPasses`) runs it no larger than the frame lands on the canvas
    (`logic/capping.ts` `cappedPassSize`, aspect kept) and draws the frame that small onto a 2D canvas
    first (`engine/engine.shrink.ts`), since the upload is the cost. Captures and renderers run at
    full size, so export keeps every pixel. If the GPU fails, video draws uncorrected and the user is
    told once per engine. What WebKitGTK
    offers is in `docs/superpowers/specs/2026-11-03-tint-webgl-check.md`.
  - `engine/engine.filters.ts` (`EngineFilters`, one per engine): the levels pass, picture and
    frame filters and viewer passes on the engine's runner. Asks the filters (`forClip`,
    `forFrame`, `clipReady`, `frameReady`), uploads each picture once (shrunk first when capped:
    an opaque `ShrinkCanvas` for video, a transparent one for images and placements) and runs its
    levels and every filter's passes in that one `run`; `over(ctx, groups)` runs passes over a
    whole canvas and draws the result back (frame filters at the top, viewer passes). The live cap
    applies to filter passes too. `EngineOptions.filters` (the sorted contributions),
    `filterTarget` and `filterFailed` (live only) wire it; `onDrawn` fires after each draw.
  - `engine/`: the v1 `PreviewEngine`. `engine.html.ts` renders and draws video layers bottom → top,
    each placed with `clipPlacement` (`project`); `engine.slots.ts` pools media elements (reused
    across clips of the same file, so splits play seamlessly; clips starting within 1.5 s are
    preloaded); `engine.sync.ts` keeps elements on the clock and re-seeks only on drift
    (`logic/drift.ts`). The clock moves during a seek and a seek flushes the sound (an audible
    tick), so a seek aims where the clock will be when it lands, using what the slot's last seek
    took (`seekCost`). A seek to the clock itself lands late on long-GOP files, stays over the
    limit and repeats every 500 ms.
    Elements are chosen by track kind: clips on video tracks get a `<video>` silenced with
    `volume = 0` (pictures only; WebKitGTK stops handing a `muted` video's frames to the canvas);
    clips on audio tracks get an `<audio>`, also for a video file's sound (same URL, sound only).
    **A `<video>` is never muted, not even for a moment.** WebKitGTK suspends a muted video that
    isn't in the viewport (ours are never on the page) by setting its GStreamer pipeline to NULL,
    and resumes it when unmuted. A suspend that lands while the pipeline is starting (after the
    file's end, a seek, a resume) leaves GStreamer's `playsink` holding a `streamsynchronizer` pad
    while the pad counter goes back to 0; the next start asks for a pad of the same name and the
    web process aborts (`Padname sink_0 is not unique in element streamsynchronizer0`, then
    `gstplaysink.c:3389: assertion failed: (it)`), freezing the app. `syncSlot` used to retry any
    refused `play()` muted: the routine `AbortError` of an element restarted at its end and paused
    when its clip ended (a take records past the composition's end) muted the picture, and Home
    then Play unmuted it. Now only a `NotAllowedError` is retried muted, and only for an
    `<audio>` (an audio element is never suspended). Checked on WebKitGTK 2.54.2 with GStreamer
    1.28.8 in a scratch window: a playing off-page `<video>` muted and unmuted at random moments
    aborts the web process with that exact message within seconds; the same element on the page,
    or never muted, doesn't. The owner's two core dumps showed the crashed pipeline was the
    `<video>` of the picture clip, half-way from READY to PAUSED.
    Images never take a media element: `engine.images.ts` (`ImageCache`) keeps decoded stills and
    frames of animated images by URL, up to a pixel budget, and rasterizes SVGs once. `imageFrames`
    (`media`) names the picture at the clip's own time, looped, and the second ahead is loaded early, so a stretched GIF
    keeps moving; scrubbing moves it too. The engine waits for the picture like any other layer, and a broken one never blocks.
    Each clip is drawn as its element's `picture` says: `source: "media"` through a media element
    as above; any other element (text, a plugin's) with its own `draw(ctx, props, env)`, at
    `clipPlacement(format, size(props), transform, fit)`, the same box the canvas tools use. Props
    are the clip's resolved values with the live override merged over them. The transform is the
    gesture's (`previewTransform`) if any, else the saved clip placed again through `followedClip` with the override (`transform`, `follow`) as its live values, so a slider dragged on a follower moves it along its path. `env.time` is the time since the clip started. A `picture.ready` that says no holds the frame like an undecoded video layer (`logic/readiness.ts`), and clips about to start are asked ahead so their art is loaded in time. `env.ensureFont` is
    `fonts.ensure`; the module redraws on `fonts.onLoaded`; `env.measure` is `canvasTextMeasure`
    (`element`) over the engine's canvas. An element without `picture` is not drawn. Swap engines by
    implementing `PreviewEngine` (`preview.types.ts`).
    **Composite:** a clip at Normal and 100% draws straight onto its target. Any other is painted on `MixCanvases.layer()` and lands once through `landLayer` (`engine.composite.ts`), with `canvasBlend` (`logic/blend.ts`) as the canvas operation, because text paints in several passes that would otherwise blend one by one. Export and captures use the same path. Under a junction a picture has no backdrop, so each clip keeps only its opacity: when both share a mode, the mix draws on `MixCanvases.result()` and that lands with the mode; when they differ it lands Normal for the overlap. Inside a placement a clip blends with what's in that composition; the placement's own mode blends with what's under it.
    **Junctions (the mixing hook):** during a junction's overlap a video track has two active
    clips. `engine.mix.ts` (`drawTrack`) draws each with the normal placement path into one of
    two pooled full-frame offscreen canvases (`MixCanvases`: default accelerated 2D canvases,
    never `willReadFrequently`), then calls the kind's `mix(ctx, a, b, progress, props, env)` on
    the main canvas in that track's place in the bottom → top order, inside `save`/`restore` in a `try/finally`: a mix that throws is logged
    once per engine and that frame shows the right picture over the left. `env` has the format,
    `kx`/`ky`, `elapsed` (seconds since the overlap started) and `random()`, a generator seeded by
    the junction id and re-created each frame (`logic/random.ts`), so noise is the same on every
    frame. A kind without `mix` (or a kind that isn't registered) draws nothing extra: the clips
    draw in start order, so the right covers the left. Nothing here is transition-specific;
    effects can reuse the hook later. The frame is painted only when both clips' frames are ready
    (rule 22). Each clip id has its own element (the pool only reuses a _free_ one), so the two
    halves of a split joined by a junction play at once; the right clip is preloaded from
    `start - 1.5 s` like any upcoming clip, and waiting pictures are silenced with volume 0, not
    `muted`, so their frame is drawable when the overlap starts. A split with no junction still
    reuses the warm element. `engine.audio.ts` sets each element's sound: linked sound clips
    overlapping under a junction get an equal-power crossfade (`soundGains`, `crossfadeGains` in
    `logic/junctions.ts`), the left clip at its end and the right at its start, which `fadeLevel`
    (`project`) folds into the clip's own fades as the export does.
    **Sound: one graph.** Every element of an audio track goes through Web Audio (`engine.audiograph.ts`; an element's own chain and the pitch worklet are in `engine.soundchain.ts`), so every sound is metered:
    `element → clip chain (pitch, EQ, pan, level, inner lines) → track bus (upmix, effects, pan, fader, solo, meter) → group bus, when the track sends to one (effects, fader, meter) → master (fader, pan, effects, meter) → monitor (mono, dim, speaker) → destination`.
    The AudioContext and its buses are made when the first sound element is attached, never after the graph is disposed; `resume()` is never awaited (`docs/superpowers/specs/2026-11-02-audio-preview-check.md`). What the mix was checked against (export loudness, pan, defaults against the old graph, and the hand checks still open): `docs/superpowers/specs/2026-11-03-sound-mix-check.md`. If they can't be made, the user is told once per engine and it isn't tried again: every element plays plain. An element takes one `MediaElementSource`, ever: once attached it stays attached and plays at volume 1. One that fails plays plain at its own level, outside the mix, and the user is told once per element with `notify("error", …)` naming the file. `busOf` never makes a context: before one exists it gives nothing. The pool hands an element to clips of any track, so `voiceSlot` calls `chain.routeTo(graph.busOf(trackId))` each frame (a no-op unless the bus changed). A clip sounds through the bus of its top-level track; a clip inside a placed composition goes through the bus of the track the placement sits on, with each inner track's volume and pan applied in its own chain through `soundInPlacement` (`project`; the export folds the same way), with the volume of the group it sends to there (`trackBus`), the pans of inner tracks summed (`placeSound(composition, track, …)` in `logic/mix.ts`). Inner tracks' `muted` silences the element as before, and so does a muted inner group (`mutedInPlacement`); inner effects (a track's, a group's, the master's) and the inner master's level aren't heard from outside.
    `engine.soundnodes.ts` holds the parts chains and buses share (`createUpmix`, `createEqFilters`, `setBand`, `createPanner`, and `glide`, which moves a parameter over 10 ms without a click). `engine.mixbus.ts` (`createMixBus`) makes a bus per audio track of the open composition, starting at its pan and level so a muted or soloed-out track never blips, and drops it when the track goes. **Groups:** a group (`MixUpdate.groups`, from `CompositionMix.buses` with live values over them) is the same bus (`createTrackBus`, centred, solo always 1, no line) made first in each `mix`, into the master; a track whose `TrackMix.busId` names one goes into its input instead of the master (`routeBus` reconnects the track's last node when that changes), and a group is dropped only after its tracks are routed away. A group's `muted` sets its fader to 0, and `mixUpdateOf` gives each of its tracks `muted` too, so they are silent and key no duck, as a muted track; a track naming a group not in the update goes to the master, as in the export; solo stays on the track buses, so a soloed track is heard through its group. A duck may sit on a group and listen to groups: `keyOf` gives a group's fader too (after its fader, before nothing: a group has no solo). `levels()` has each group's meter under its id beside the tracks'; the master meter sits after the master fader, before the monitor. **Master:** its fader is a `createFaderLevel` as a track bus's (its `volumeDb` plus its input trim `trimDb`, the same stage as the export's master level, 0 when `muted`, or its `volumeLine` with the volume on top, followed with the buses on `follow`), then a `StereoPannerNode` for its `pan` (a balance with a track pan's law, as the export's `pan_filter`), then its effects. A muted master meters and measures silence, as a muted track's bus does: the meters and the loudness show what is heard and exported. Mono sums both sides into each speaker through a `ChannelMergerNode` at half each, Dim is −20 dB. A track's `muted` sets the bus fader to 0 and solo sets a gain of its own after it to 0, never the elements, so sync isn't disturbed. **Volume line:** the fader is set by `engine.line.ts` (`createFaderLevel`, one per bus, `TrackBus.level`): the track's volume, 0 when muted, or with a `TrackMix.volumeLine` the line with the volume as an offset in dB on top (`logic/line.ts`: `lineLevel`, `lineSchedule`). It is the same node the fader is, so the effects before it, a duck's key (taken after it) and solo (after it) keep their order, as in the export; mute and solo work as without a line, and switching Mix A/B swaps the line with the rest. While playing, the line is scheduled on the fader's gain with `linearRampToValueAtTime` a second ahead, at each key (`project`'s `keyMoments`, and 1 ms before each, so a Hold stays a step) and every 100 ms of timeline time between (a straight dB line is a curve in gain; these are the times the export reads it at), topped up when less than half a second is left, never past `until` (the render's: where playback stops or goes round, a loop's end or the composition's; the controller passes it, so a wrap or the end has no blip), and scheduled again (after `cancelAndHoldAtTime`, or a hold by hand where WebKit lacks it, reaching the line over 10 ms) when the playhead is more than 100 ms from where the schedule has it (a seek, a loop) or the line, the volume or the mute changes. Paused, it glides to the line's level at the playhead. The engine calls `SoundMix.follow(time, playing, until)` at each `render` (`SoundGraph.follow`, `MixBus.follow`), which costs nothing for a bus without a line. Inside a placed composition, an inner track's line applies too, as its volume does: the engine gives each voice the lines of the inner tracks around it (`Voice.lines`, `Nesting.lines`), each a `LineAt` with its `shift` (its composition's time minus the playhead's), and the element's chain plays them on a gain of its own after the level (`SoundChain.follow`, the same `createFaderLevel`, started at the playhead), the lines added in dB, while the level glides each frame as before. Nothing is allocated per frame for it: the lists come from the engine's `createLineLists` (`engine.line.ts`), made once per (lines above, line, shift) and handed back the same, so a chain and a fader compare them by identity and only a change reaches `FaderLevel.set`; a voice outside a placement has `NO_LINES`; the engine's `SoundClock` is one object set in place at each `render`. The scheduler maps timeline time 1:1 to the context's: the clock plays at 1x. Solo outlives a deleted track and a switch of composition, so `mixUpdateOf` keeps only the solo ids that are tracks of the open composition; none left means no solo. `engine.meters.ts` (`createMeter`) splits a bus to one `AnalyserNode` per side and reads the largest sample of the last 2048. `engine.soundmix.ts` (`createSoundMix`) is the engine's sound side: the graph, the `LiveSound` from the controller (`setSound`), `levels()`, `heard` (`createSoundAtSpeed`), and `update(project, composition)`, called at each frame, which calls `graph.mix(mixUpdateOf(...))` (`logic/mix.ts`) only when the project's tracks, the open composition or the `LiveSound` changed, never per frame; live values win over the document's until cleared. A picture-only engine has no graph.

    **Effects.** A bus plays its track's `effects` (`SoundEffect`, from `project`) in the user's order: `input → [effects] → pan → fader → solo → meter`; the master's run after its fader and before its meter, the loudness tap and the monitor, so a limiter there is the last thing before them. `engine.effects.ts` (`createEffectChain(context, from, to, dynamics)`) makes a chain between two nodes it doesn't own. `eq` is the clip's six biquads (`createEqFilters`/`setBand`); every other live kind is one `AudioWorkletNode` running `dynamics.worklet.ts`, a thin wrapper over `createEffectRunner` (`logic/effects.ts`), which runs any kind by `kind` on stereo blocks over the pure ports in `logic/` (one detector for both sides). Noise reduction plays a rendered file instead, so it has no node. A chain is rebuilt only when its kinds, order or ids change, or the worklet becomes ready or fails; any other change posts the effect to its node (`DynamicsCommand`, when the effect object changed) or sets the biquads, and the processor keeps its state, so a drag doesn't click. Off, an effect passes the sound through and its state stands still; turned back on it starts from rest (envelope, de-esser, the limiter's lookahead and schedule), so no old sound replays. A duck's node has a second input: the sum (a stereo `GainNode`) of the tracks it listens to after their faders and before their solo gain, so the key follows their level and mute but not solo, which is only how the user listens and which the export doesn't have; `mix` makes and levels every bus first and sets chains after, so the listened buses exist, and rewires the key when `listensTo` changes or a listened bus comes or goes. The tracks inside a placed composition keep their effects to themselves: from outside only their volume and pan are heard. The worklet's runner (`EffectRunner.takeReduction`) tracks the lowest gain of a compressor, makeup left out, and the worklet posts it as dB (a plain number, `EffectChain.reduction()`/`EffectStage.reduction()` sum it per bus, `MixBus.reduction(target)`). `engine.dynamics.ts` (`createDynamicsNodes`) loads the worklet once per context, in the background; until it's ready, dynamics effects pass dry. If it can't load, a node can't be made or a processor fails later (`onprocessorerror`), the user is told once per engine, the chains rebuild without worklet nodes and play dry from then on; playback never breaks. The limiter delays its bus by 255 samples at 48 kHz (its 5 ms lookahead plus the true-peak interpolator's 16), as the export's chain does.

    **Loudness.** `engine.loudness.ts` (`createLoudnessTap`) loads `loudness.worklet.ts` (bundled as a URL with `?worker&url`, the way `engine.soundchain.ts` loads the pitch processor) and connects the master, after its fader, to it, beside the monitor (Mono, Dim and the speaker don't reach it); the node also goes to the destination so the context keeps running it, but it writes no output. The worklet is a thin wrapper over the pure `createLoudnessMeter` (`logic/loudness.ts`: K-weighting derived for any sample rate in `kweight.ts`, 400 ms blocks every 100 ms, gating in `gating.ts` as histograms of a hundredth of an LU so memory doesn't grow however long it plays, true peak by 4x oversampling in `truepeak.ts`, with the filter FFmpeg's resampler builds by default (a Kaiser-windowed sinc, beta 9, 32 taps per phase), so it reads as `ebur128`'s true peak does; the limiter listens with the same `PHASES`) and posts a reading every 100 ms; the main thread keeps the latest. It works only while active: the engine calls `SoundMix.setPlaying` at each `render` (with `playing`) and on `pauseAll`, the tap posts `{ active }` to the worklet only when it changes (`LoudnessCommand`), and a tap that loads later starts from the graph's last state. Inactive, the worklet neither measures nor posts, so paused time doesn't count and the last reading stands (momentary and short-term don't fall to −∞ on a pause). `resetLoudness()` posts `{ reset: n }`, and readings from before it (older `generation`) are ignored. The graph opens it once per engine: if the worklet can't load, or its processor fails later (`onprocessorerror`), the user is told once and loudness reads null from then on while everything else goes on. The master's gain is set outright by the first mix; later changes glide.
